# 구름항로 디자인 시안 (D-185 · D1)

구름항로 게임판의 분위기 시안 3개. 앱 코드와 무관한 **단독 HTML**(외부 의존 0 — 그림은 전부 인라인 SVG·CSS, 연출은 CSS 키프레임 + 작은 JS)이다.
파일을 브라우저로 바로 열면 된다.

| 파일 | 이름 | 한 줄 |
|---|---|---|
| [option-a.html](option-a.html) | **A 솜구름 그림책** | 종이 오리기 느낌의 둥근 섬, 통통 튀는 열기구 말. 밝고 귀엽다 |
| [option-b.html](option-b.html) | **B 바람 항해도** | 잉크 선·해칭·도장으로 그린 옛 항로 지도, 종이비행기 말. 차분하고 읽기 좋다 |
| [option-c.html](option-c.html) | **C 등불 축제의 밤** | 밤하늘 위 빛나는 유리 섬, 등불 말, 불씨와 빛의 자취. 화려하다 |

## 보는 법

- 장면: 4인 · 9라운드 · 땅 16칸 중 10칸 소유(땅만·천막·상점·풍등탑 섞임, 이끼섬 독점, 별사과 과수원 축제).
- **[🎲 주사위]** 를 누를 때마다 다음 차례가 재생된다 — 구입·건설 → 통행료 → 바람 편지 → 비행 → 파산 → 결과 화면. 이름표 버튼으로 그 연출만 바로 볼 수 있다.
- 위쪽 줄: **A/B/C** 시안 이동 · **라이트/다크** · **375px 폭**(휴대폰 틀) · **연출 줄이기**(`prefers-reduced-motion` 과 같은 동작 — OS 설정이 켜져 있으면 자동).
- 실제 375px 화면에서도 가로 스크롤이 없다(세 시안 모두 `scrollWidth == 375` 확인).

구성 요소는 지금 게임판 그대로다 — 헤더 배지, 좌석 줄(현금·차례·파산), 7×7 테두리 판 24칸(소유 색·건물 단계·축제), 말, 가운데(주사위·차례 글·사건 줄·편지 더미), 결정 패널(구매 단계 고르기), 편지 카드, 결과 화면. 바뀐 것은 분위기뿐이고, 데스크톱에서 좌석·패널을 판 오른쪽에 둔 것만 배치 제안이다(좁은 화면은 지금처럼 한 줄).

칸 그림 14종(섬 8 + 특수 6)과 건물 4단계(깃발·천막·상점·풍등탑)는 **모양은 공통, 칠·선은 시안 CSS** 가 정한다(24×24 SVG, 클래스 `f/a/d/l`·`bf/ba/bw/bd`). 그래서 시안을 바꿔도 그림 자산은 한 벌이다.

## A — 솜구름 그림책

- **콘셉트**: 그림책 속 하늘 산책. 칸은 둥근 종이 카드에 섬 색 언덕이 얹힌 모양, 가운데엔 무지개와 떠다니는 구름. 모든 것이 눌리고 튀는 젤리 같은 손맛.
- **팔레트**: 하늘 `#cdeaff→#ffe3ee`, 종이 `#fffaf2`, 글자 `#45385a`, 강조 분홍 `#ff8fab`. 좌석 파랑 `#3f86f5`·분홍 `#f0558a`·초록 `#1faa74`·주황 `#f08a1d`. 섬은 파스텔 8색. 다크는 해 질 녘 보라(`#29284f→#493461`).
- **글자**: 둥근 고딕(`ui-rounded` 계열, 굵게).
- **연출**
  - 주사위: 통통 튀며 구르고 착지 때 납작해졌다 돌아옴
  - 이동: 열기구 말이 칸마다 폴짝(늘었다 줄었다), 밟힌 칸이 살짝 눌림
  - 구입: 칸이 부풀며 종이 꽃가루 / 건설: 건물이 아래에서 뿅 솟고 별
  - 통행료: 칸이 흔들리고 별 동전이 포물선으로 주인 좌석까지, 숫자가 오르내림
  - 편지: 더미에서 카드가 날아와 탄력 있게 뒤집힘
  - 비행: 말이 커지며 구름 점선 길을 따라 날아감
  - 파산: 말이 흔들리다 잿빛으로 떨어지고 빗방울, 땅이 하나씩 풀림
  - 결과: 종이 꽃가루 3번
- **구현 난이도**: **낮음~중간**. 전부 CSS transform 키프레임 + 작은 입자. 기존 구조와 가장 가깝다.
- **예상 용량**: CSS 약 9KB + 그림(SVG 문자열) 약 6KB. 래스터 0.

## B — 바람 항해도

- **콘셉트**: 항해사의 낡은 항로 지도. 모눈 종이 위에 잉크 선으로 그린 칸, 섬 색은 위쪽 해칭 띠, 칸 번호(00~23), 가운데 나침반. 소유·사건은 **도장**으로 찍힌다. 다크는 청사진.
- **팔레트**: 종이 `#f2e9d3`, 잉크 `#1c2c44`, 도장 빨강 `#a8321b`, 청록 `#1b6461`. 좌석 잉크 파랑·빨강·초록·황토. 다크는 `#0f2746` 바탕에 밝은 선(`#dbe9fb`).
- **글자**: 이름은 명조(세리프), 숫자는 고정폭.
- **연출**
  - 주사위: 공항 안내판처럼 위아래로 착착 넘어가다 쿵 찍힘(마름모 눈)
  - 이동: 종이비행기가 진행 방향으로 머리를 돌려 미끄러지고, 지난 칸에 잉크가 번졌다 마름
  - 구입: "매입" 도장이 쾅 / 건설: 건물이 설계도처럼 선부터 그려지고 색이 참 / 독점: "독점" 도장
  - 통행료: "통행료" 도장 + G 전표가 곧게 날아감
  - 편지: 줄무늬 테두리 전보가 옆에서 미끄러져 들어와 위아래로 뒤집힘
  - 비행: 빨간 점선 항로가 흐르고 비행기가 커져 그림자를 끌며 건넘
  - 파산: 말이 빙글 돌며 추락, 좌석에 "파산 · 항로 폐쇄" 도장, 땅마다 "말소"
  - 결과: 항해 일지 표 + 나침반 별
- **구현 난이도**: **중간**. 도장은 `::after` 한 종류로 돌려 쓰지만 비행기 머리 방향(이동 방향 각도)과 선 그리기(`pathLength`)가 추가 작업.
- **예상 용량**: CSS 약 10KB + 그림 약 6KB. 래스터 0.
- **장점**: 작은 칸에서도 글자·경계가 가장 또렷하다(375px 가독성 1위). 움직임이 짧아 조작을 가장 덜 막는다.

## C — 등불 축제의 밤

- **콘셉트**: 구름 위 섬들의 등불 축제. 어두운 하늘에 별·달·등불 줄, 칸은 섬 색으로 은은히 빛나는 유리. 소유는 빛의 색, 건물은 불 켜진 창. 라이트는 노을(살구→분홍→보라).
- **팔레트**: 밤 `#2e1c5a→#0e1132`, 글자 `#fbeed2`, 금빛 `#ffc866`/`#ffb347`. 좌석 호박·장미·옥·연보라. 섬은 보석 색 8종. 라이트는 글자 `#33203e`, 좌석·섬 색을 한 단계 짙게.
- **글자**: 가는 고딕 + 넓은 자간.
- **연출**
  - 주사위: 빛을 내며 3D 로 돌고 멈출 때 번쩍
  - 이동: 등불 말이 떠가고 **지난 칸이 차례로 켜졌다 서서히 꺼짐**(빛의 자취)
  - 구입: 칸에서 빛의 고리가 퍼지고 불씨가 떠오름 / 건설: 전등처럼 깜빡이다 켜짐
  - 통행료: 칸이 붉게 맥박, 불씨 구슬이 큰 곡선으로 주인 좌석까지, 좌석이 번쩍
  - 편지: 쪽지가 위에서 하늘하늘 내려와 천천히 뒤집힘
  - 비행: 풍등처럼 떠올라 혜성 꼬리 빛줄기를 따라감
  - 파산: 등불이 깜빡이다 꺼지고 연기, 땅의 빛이 하나씩 사그라듦
  - 결과: 불꽃놀이 3번
- **구현 난이도**: **중간~높음**. `box-shadow`·`drop-shadow` 빛이 많아 저사양 휴대폰 60fps 확인이 필요하고(빛 번짐 줄인 단계 준비), 라이트 테마를 따로 맞춰야 한다.
- **예상 용량**: CSS 약 10KB + 그림 약 7KB. 래스터 0.

## 위험·남은 일

- **연출이 조작을 막으면 안 된다**(D-185 원칙): 시안은 한 차례를 3.5~5초로 보여 주지만 실제 서버 이벤트는 한꺼번에 온다. 연출 큐는 다음 이벤트·내 결정 패널이 오면 **건너뛰기**해야 하고, 턴 타이머는 연출과 무관하게 흘러야 한다.
- **작은 칸**: 375px 에서 칸은 약 47px. 말이 칸 그림·이름 일부를 가린다 — 구현 때 말 있는 칸의 이름 처리(말을 줄이거나 칸 밖으로 살짝 내기)를 정해야 한다.
- **좌석 구분이 색 위주**: B·C 는 말에 번호(①~④)가 있고 A 는 표정만 다르다. A 를 고르면 번호나 무늬를 더한다.
- **글꼴**: 외부 글꼴 없이 기기 글꼴 묶음만 썼다. A 의 둥근 글씨·B 의 명조는 기기마다 다르게 보인다(안드로이드는 기본 고딕으로 떨어짐) — 그대로 갈지, 제목용 글꼴 일부만 넣을지 결정 필요.
- **C 성능**: 빛 번짐(`filter`·큰 `box-shadow`)이 많다. 저사양 기기에서 프레임 확인 뒤 단계별로 줄일 수 있게 만든다.
- **통행료 숫자**: 시안의 독점 ×1.5 표시는 단순 반올림이다(실제 값은 서버가 보냄).
- 시안은 최신 브라우저 기능(`container query`·`color-mix`)을 쓴다. 앱에 넣을 때는 지금 CSS 관례(clamp·전역 토큰)에 맞춘다.
- 독창: 판 배치(7×7 테두리)는 지금 구현 그대로이고, 칸·건물·말·카드·도장 그림은 모두 새로 그렸다. 다른 게임의 그림·상표를 쓰지 않았다.

## 2차 — 연출 고도화 (D-219 · D-187)

그림책 테마는 그대로 두고 연출만 올렸다. 서버·스토어·룰·D-186 머리 줄은 건드리지 않았다.

**되돌리기**: `client/src/features/cloudroute/theme.ts` 의 `CLOUD_ROUTE_FX_LEVEL = 1` (D-218 연출로). `CLOUD_ROUTE_THEME = 'classic'` 이면 기본 모습. 연출 큐 따라잡기는 단계와 무관하게 켜져 있다.

### 먼저 고친 것 — 연출 큐 따라잡기

1차 리스크: 봇 차례가 3번 이어지면 화면이 늦게 따라왔다(봇은 0.7초마다 행동, 한 차례 연출은 제 속도로 3초쯤). 배속을 두 값으로 정한다(`useCloudRouteFx.ts` `paceFor`).

| 상황 | 배속 |
|---|---|
| 밀린 연출 0 · 1 · 2개 | 1 · 1.2 · 1.5배 |
| 밀린 연출 3 · 4 · 5개 이상 | 3 · 4.5 · 6배 (빨리 감기 — 기다리던 걸음도 새 배속으로 줄인다) |
| 다음 묶음이 0.5 · 1.4 · 2.4초 넘게 기다림 | 1.8 · 3 · 5배 이상 |
| 내 결정이 와 있는데 남의 연출이 남음 | 3.4배 이상(1개 밀림 4.5, 2개 이상 6배), 4개 이상 밀리면 건너뜀 |
| 8개 이상 밀림 · 다음 묶음이 4초 넘게 기다림 | 건너뜀 — 그 이벤트 뒤의 화면 값만 그린다 |

예전에는 14개가 쌓여야 건너뛰었고(가장 빨라도 3.4배), 이미 기다리던 걸음은 느린 배속 그대로 끝까지 갔다. 큐가 비면 늘 스토어(최신)를 그린다. `cloudrouteFxCatchUp.test.tsx` 가 고정한다.
