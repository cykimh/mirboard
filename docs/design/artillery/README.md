# 씨앗포 디자인 시안 (D-185 D1)

씨앗포 게임판의 분위기 시안 3개. 앱 코드는 건드리지 않았고, 세 파일 모두 **외부 의존 없는 단독 HTML**(인라인 CSS·Canvas JS)이다.
파일을 브라우저로 바로 열면 된다.

| 파일 | 이름 | 한 줄 |
| --- | --- | --- |
| [`option-a.html`](option-a.html) | **A 수채 그림책 정원** | 종이 위에 번진 물감과 세피아 잉크 선 — 조용하고 다정하다 |
| [`option-b.html`](option-b.html) | **B 말랑 클레이 장난감** | 원색 점토 덩어리, 큰 눈, 눌렸다 튕기는 움직임 — 가장 밝고 장난스럽다 |
| [`option-c.html`](option-c.html) | **C 해 질 녘 실루엣** | 노을을 등진 그림자극, 좌석 색은 등불 빛으로만 — 가장 차분하고 극적이다 |

## 보는 법

- **[발사]** — 조준(0.45초) → 발사 반동(200ms) → 비행 → 착탄 폭발(0.6초) → 피격(400ms) → 낙하. 표적(도토리단)은 체력 58 로 시작해
  콩알 두 발이면 **쓰러짐**까지 본다. 적이 다 쓰러지면 버튼이 [처음으로]가 된다.
- **씨앗탄 5종** 버튼 — 콩알·호박탄·덩굴탄(둔덕을 쌓는다)·알밤탄·홀씨탄(꼭대기에서 셋으로 갈라진다).
- **바람** 슬라이더(−10~+10) — 바람 표시와 하늘의 바람 연출, 탄도가 같이 바뀐다.
- **밤(다크)** — 다크 테마 팔레트. **연출 줄이기** — `prefers-reduced-motion` 과 같은 상태(기기 설정이 켜져 있으면 처음부터 체크).
- 화면 구성: 4인 판 데스크톱 → 휴대폰 375px(전장 폭 340px, 앱의 `uiBoost` 와 같은 배율) → 캐릭터 시트(포대 3종 × 상태 5) →
  씨앗탄·폭발·둔덕·궤적·체력바·바람 견본 → 팔레트 → 연출 목록.

**흉내인 것**: 지형·출발 자리·힘 계산(각도를 정해 두고 표적에 맞는 힘을 찾는다). 탄도 상수·구멍 반경·피해 식·맞는 범위·상태 길이
(반동 200ms·피격 400ms·폭발 36틱)·그리는 순서는 `docs/rules-artillery.md`·`unitPose.ts`·`draw.ts` 와 같게 맞췄다.
포대는 실제 크기(화분 폭 약 11칸 — 데스크톱에서 16px 남짓)로 그렸다. 얼굴 같은 잔 그림은 캐릭터 시트에서 본다.

  포대는 볼이 발그레한 화분 — 눈 두 점과 입만.

## 시안 B — 말랑 클레이 장난감

- **콘셉트**: 점토 장난감 상자. 외곽선 없이 덩어리·그늘·광택으로만 빚는다. 흙은 자갈이 박힌 초콜릿색 단면에 흘러내린 풀 물결.
  모든 움직임이 스쿼시·스트레치. 도토리포는 갈색 깍정이 테두리, 민들레포는 물방울무늬 테두리로 화분 자체가 다르다.
- **팔레트** (라이트 / 다크)

  구슬 줄 궤적 / 12각 별이 오버슈트로 커졌다 쏙 줄어듦 + 흙덩이·색종이(착탄, 흔들림 4칸) / 초록 덩어리가 "뿅"(둔덕) /

## 시안 C — 해 질 녘 실루엣

- **콘셉트**: 종이 오림 그림자극. 섬·포대·흙 조각은 짙은 실루엣, 윗면에만 노을빛 테두리 한 줄. 좌석 색은 화분의 **등불 띠·눈·포구 불씨·
  빛 번짐**으로만 드러난다. 라이트 테마 = 해 질 녘(큰 해), 다크 테마 = 달밤(별·푸른 테두리 빛).
- **팔레트** (라이트 = 노을 / 다크 = 달밤)

| 쓰임 | 노을 | 달밤 |
| --- | --- | --- |

| 실루엣 / 윗면 | `#1c1428` / `#3e2846` | `#05070f` / `#121a34` |
| 테두리 빛 / 빛 번짐 | `#ffce8c` / `#ffd9a0` | `#96beff` / `#bcd4ff` |

- **글꼴**: 가는 고딕. 이름표는 반투명 어두운 판 + 왼쪽 좌석 색 띠 + 1칸 두께 빛 체력선(밝은 하늘 위에서도 글자 대비 확보).
- **연출**: 등불 띠가 숨 쉬듯 밝아짐(대기) / 눈빛이 가늘어지고 위에서 빛줄기(조준) / 포구 섬광 + 불티 8개(반동) /
  머리로 갈수록 굵어지는 빛 꼬리(궤적, 가산 혼합) / 흰 섬광 90ms → 주황 빛 덩이 + 빛 고리 + 실루엣 흙 조각 + 불티 + 연기(착탄, 흔들림 3칸) /
  초록 빛 + 말리며 솟는 덩굴(둔덕) / 실루엣이 빛으로 뒤집혀 번쩍(피격) / 등불이 깜빡이다 꺼짐(쓰러짐) / 빛 막대 + 바람 줄 + 꽃가루(바람).

## 연출과 앱 규칙

- 반동(200ms)·피격(400ms)·폭발(36틱)은 `unitPose.ts`·`replay.ts` 의 창 그대로다 — **재생 길이를 늘리지 않는다**.
- 쓰러짐은 0.7초짜리 한 번 재생. 앱에서는 "그 단계가 끝나 사라지기 전까지"만 보이므로 단계가 짧으면 중간에 끊긴다(마지막 프레임부터 보여도
  읽히게 그렸다).
- 입자(꽃잎·흙덩이·불티)는 최대 1.5초 남는다. 판정과 무관한 덧그림이라 다음 차례 조작을 막지 않는다.
- `prefers-reduced-motion`: 화면 흔들림·입자·대기 움직임·깜빡임·섬광을 끄고, 피격은 옅은 덧칠 한 번, 반동은 물러난 한 장면. 탄 비행과
  폭발 자체(정보)는 남긴다.

## D-227 스프라이트 시트로 옮기는 방법

시안의 그리기 코드는 일부러 스킨 계약과 같은 모양이다: **몸은 오른쪽을 보고 발(화분 바닥 가운데) 기준, 포신은 0° 를 가리키고 회전축 기준,
좌석 색은 따로 칠한다.** `src/theme-*.js` 의 `body`·`barrel`·`seed`·`boom` 이 그대로 시트 프레임이 된다.

### 시트에 그대로 들어가는 것 (`atlas.png` + `atlas.json`, 코드 변경 없음)

| 항목 | 애니메이션 이름 | 프레임 |
| --- | --- | --- |
| 포대 몸 3종 × 5상태 | `unit.{SPROUT\|ACORN\|DANDELION}.{idle\|aim\|recoil\|hit\|down}` | 대기 4(`frameMs` 260, 반복) · 조준 2(260) · 반동 3(66, 한 번) · 피격 4(100, 한 번) · 쓰러짐 5(140, 한 번, `barrel:false`) = 종류당 18 |

**생성 방법.** 지금 생성기(`scripts/generate-artillery-sprites.mjs`)는 Node 기본 모듈만 쓰는 자체 래스터라이저여서 곡선·그라데이션·알파가 많은
이 시안들을 옮기기엔 품이 든다. 대신 **시안의 Canvas 코드를 그대로 돌려 내보낸다**:

1. `src/theme-*.js` 를 읽어 프레임을 격자로 그리는 내보내기 페이지(HTML 한 장)를 만든다 — 포대는 좌석 색 대신 흰색으로 한 번(`tint`),
   투명 화분으로 한 번(`frames`) 그린다.
2. 이미 있는 Playwright(`client` devDependency, D-142)로 그 페이지를 열어 `canvas.toDataURL()` → `atlas.png`, 프레임 좌표 → `atlas.json` 을
   `client/public/artillery/skins/{garden|clay|dusk}/` 에 쓴다(결과물을 커밋 — 빌드 때 생성하지 않는다).
3. `npm --prefix client run test -- artillerySkin` 으로 형식·프레임 범위·3종×5상태·씨앗 5종 검사.

글꼴은 시트에 들어가지 않으므로(이름표는 Canvas 글씨) 내보내기 결과는 기기와 무관하다. 가산 혼합(C 의 빛)은 시트로 굽지 못하니 일반 알파로
굽는다 — 조금 덜 밝다.

### 코드가 필요한 것 (S6b 가 끝난 뒤, 스킨 층 안에서)

지금 시트 스킨은 하늘·구름·궤적·이름표를 도형 스킨 것으로 그린다. 아래는 시트만으로는 안 된다.

| 항목 | 방법 | 크기 |
| --- | --- | --- |
| 하늘·구름 바다·궤적·이름표·체력바 | 시안마다 `ArtillerySkin` 구현 한 파일(`skins/{이름}Skin.ts`) — 포대·씨앗·폭발은 시트 스킨에 맡기고 나머지 5개 메서드만 덮어쓴다. 시안 JS 를 거의 그대로 옮긴다 | 파일당 150~250줄 |
| 흙 질감(A 가장자리 물감 고임 · B 자갈·풀 물결 · C 윗면 테두리 빛·풀잎) | 스킨의 `terrainImage(mask)` 를 덮어쓴다(시안의 `soil`·`above`). 마스크가 바뀔 때만 불려 비용 없음 | 40줄 안팎 |
| A 의 부드러운 흙 | `drawScene` 이 `imageSmoothingEnabled = false` 로 고정 — 스킨이 고르게 한 줄 바꿔야 한다(S6b 와 같은 파일) | 1줄 |
| 차례 표시(번짐·화살표·빛줄기) | `drawUnit` 의 `isTurn` 으로 스킨이 그린다 — 계약 그대로 | 스킨 안 |

## 위험·확인할 것

- **포대가 작다.** 화분 폭 11칸은 데스크톱 16px, 휴대폰 9~12px. 캐릭터 시트의 얼굴·광택은 게임판에서 거의 안 보인다. 세 시안 모두 실루엣과
  색으로 구분되게 했지만, 고른 뒤 D3 에서 그림만 1.2~1.3배 키울지(맞는 범위는 그대로) 정해야 한다.
- **C 는 좌석 색이 빛으로만 보인다.** 등불 띠·빛 번짐·이름표 띠 세 군데에 넣었지만 A·B 보다 약하다. 팀 색은 좌석 띠(DOM)에 의존한다.
  C 는 라이트 테마에서도 전장이 어둡다 — 밝은 앱 화면 안에서 어울리는지 D4 에서 봐야 한다.
- **성능.** C 는 프레임마다 방사형 그라데이션(빛 번짐)을 많이 만든다 — 구현 때는 빛 번짐을 미리 그린 작은 캔버스로 바꾼다. A 의 하늘(번짐 +
  종이 결)은 테마가 바뀔 때만 다시 그리는 캐시가 필요하다. B 가 가장 가볍다.
- **A 는 손맛이 한계.** 코드로 그린 수채는 "수채 느낌"까지다. 진짜 붓 자국을 원하면 손그림(같은 프레임 틀)이 필요하고 용량이 가장 크다.
- **시안의 지형·힘 계산은 흉내.** 실제 맵 생성기·대본과 다르다. 연출 시간은 앱 값에 맞췄지만 실제 봇 판에서 다시 확인해야 한다(D4).
- **S6b 와 겹침.** 코드 쪽(스킨 파일·계약 확장·`drawScene` 한 줄)은 S6b 뒤에. 그 전에 할 수 있는 것은 시트 PNG·JSON 생성뿐이다.
