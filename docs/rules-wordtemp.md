# 낱말 온도 룰 명세 (Word Temperature Rules)

본 문서는 Mirboard 낱말 온도 룰의 **단일 진실 공급원**이다. 코드(S1 순수 엔진)는 이 문서를 따르고, 어긋나면 코드를 고치거나
이 문서와 결정(`docs/decisions.md`)을 함께 고친다. 구현이 붙으면 각 절 끝에 `rules-onecard.md` 와 같은 표기(**코드:** / **테스트:**)로
위치를 단다. 경로는 `server/src/{main,test}/java/com/mirboard/domain/game/wordtemp/` 기준(예정).

> **상태:** **룰 v2 (D-320, 2026-11-27) — 차수 5번·기준 온도 70/75/80/85/88(5차는 관제가 90 → 88 조정)·힌트는 낼 때마다 모두에게 공개, 기준을 넘기면 바로 추리** · **S3 — 클라 게임판(D-319, §18.2)** · S2 서버 연결(D-316 어댑터·정의·표 싣기 · D-317 실시간 채점기 · D-318 기록) · S1b 순수 엔진·봇 정책·시뮬레이션(D-315) · 채택 D-310 · 룰 D-311 · 채점 방식 D-312 — 2026-11-25. 코드·테스트 위치는 §18. 공개 설정 `MIRBOARD_WORD_TEMP_STATUS` 는 S4 전까지 `DISABLED`.
> 설계(포트 대응·비동기 채점 경로·데이터 만들기·단계)는 `docs/plans/wordtemp.md`, 검토 기록은 `docs/plans/word-temperature-review.md`.
>
> **독창 게임.** "낱말을 내면 정답과 얼마나 가까운지 숫자로 알려 주고, 그 숫자를 보고 정답을 맞힌다"는 **일반 메커니즘**만 가져왔다.
> 이름·용어·점수 세부·화면·문구는 이 문서에서 새로 정했고, 방송 프로그램의 이름·용어·연출은 쓰지 않는다. 검토에서 바로 오지 않고
> 이 문서에서 처음 정한 항목은 **[결정]**, S1 측정·시험판으로 조정할 값은 **[수치]** 로 표시하고 §15 에 모았다.

## 1. 말 정하기

| 말 | 뜻 | 코드 표기(예정) |
| --- | --- | --- |
| 정답 낱말 | 출제자가 이번 출제 차례에 숨기는 낱말. **정답 은행**에서만 나온다 | `answer` |
| 출제자 / 추리자 | 이번 출제 차례에 정답을 숨긴 사람 / 나머지 살아 있는 좌석 | `setterSeat` / guessers |
| 힌트 | 출제자가 내는 관련 낱말(한글 명사) | `Hint{text, temp, attempt, status}` |
| 온도 | 힌트와 정답의 가까움, **정수 0~100**. 서버가 매긴다(§6) | `temp` |
| 차수 | 한 출제 차례 안의 "힌트 → 추리" 한 바퀴. 최대 **5차**(D-320) | `attempt` 1~5 |
| 출제 차례 | 한 사람이 정답 하나로 진행하는 1~5차 | `turnNo`(판 전체 일련번호) |
| 라운드 | 살아 있는 모두가 한 번씩 출제하는 한 바퀴 | `round` 1~R |
| 기준 온도 | 차수마다 정해진 온도(§3.4). 이 온도 이상의 힌트가 나오면 힌트 단계가 끝난다("통과") | `floor`·`floorMet` |
| 같은 말 | 정답 은행이 낱말마다 가진 동의어·표기 변형 목록(휴대폰 ↔ 핸드폰, 케이크 ↔ 케익) | `aliases` |

온도의 띠(화면 색·봇·검수가 같이 쓴다): **96 이상** 거의 정답 · **75~95** 뜨거움 · **40~74** 미지근 · **40 미만** 차가움.

## 3. 판의 흐름 (단계)

```
라운드 r 시작
  WORD_SELECT (20초, 모두 같이)          각자 후보에서 이번 라운드 정답 낱말 1개 고름
  ┌ 출제 차례 (출제 순서대로, 살아 있는 좌석마다)
  │   차수 a = 1..5
  │     HINT          (힌트 제한 T초)    출제자가 힌트 0~10개. 낼 때마다 낱말·온도가 모두에게 공개. 기준 온도 이상이 나오면 바로 끝
  │     GUESS         (30초)             추리자마다 답 1개(또는 패스). 동시 공개
  │     ATTEMPT_RESULT(5초)              차수 결과 보기
  │   └ 누가 맞혔거나 · 5차가 끝났으면 →
  │     TURN_END      (6초)              정답 낱말 공개
  └ 다음 출제자
라운드 끝 → 다음 라운드(WORD_SELECT) 또는 MATCH_ENDED
```

- 단계 이름(`phaseName`): `WORD_SELECT`·`HINT`·`GUESS`·`ATTEMPT_RESULT`·`TURN_END`·`FINISHED`. 대기실(LOBBY)은 플랫폼 몫이라 단계가 아니다.
- 모든 단계는 **상태에 둔 시작 시각 + 엔진 타이머**로 끝난다(§9). 기다릴 사람이 모두 끝내면 바로 넘어간다.

### 3.1 낱말 고르기 (`WORD_SELECT`)

- 판 시작 때 좌석마다 **후보 낱말**을 받는다 — 라운드 수 R 에 대해 `max(3, R+1)` 개(짧게·보통 3개, 길게 4개) **[결정]**. 한 사람의 후보는
  서로 다른 범주, 판 전체에서 겹치지 않고 서로 같은 말 관계도 아니다. 후보는 **본인만** 본다(§12).
- 라운드마다 남은 후보 중 1개를 고른다(`SELECT_WORD`). 20초 **[수치]** 안에 안 고르면 서버가 남은 후보에서 무작위로 정한다.
  마지막 라운드에도 고를 것이 2개 남는다.
- 쓰지 않은 후보는 판이 끝나도 공개하지 않는다.

### 3.2 힌트 (`HINT`) — D-320

- 출제자만 행동한다. 차수당 힌트 **최대 10개**, 시간은 방의 힌트 제한(§2).
- **힌트는 채점되는 대로 모두에게 공개된다** — 낱말과 온도가 출제자·추리자·관전자 모두에게 간다(공개 이벤트 `HINT_SCORED`). 표 밖 낱말은
  "채점 중"으로 먼저 보이고(`HINT_PENDING` — 낱말도 보인다), 무효가 되면 사라지며 개수를 돌려준다(`HINT_VOID`).
  힌트는 차수가 지나도 그 출제 차례 내내 쌓여 보인다(차수 번호와 함께).
- **기준 온도 이상인 힌트가 나오면 힌트 단계가 그 자리에서 끝나고 추리로 간다**("통과" — 그 힌트가 통과 힌트다). 기준은 §3.4.
- 시간이 끝나거나 10개를 다 쓰도록 기준을 못 넘기면 **그래도 추리로 간다** — 그 차수는 "기준 못 넘김"이라 아무도 못 맞혀도 출제자는 이 차수
  점수가 없다. **힌트 0개로 시간이 끝난 것도 같다**(추리로 간다, 출제자 0점).
- 1개 이상 냈으면 **[그만 내기]**(`END_HINTS`)로 일찍 끝낼 수 있다 — 기준을 못 넘긴 채 추리로 간다(더 낼 낱말이 없을 때 시간을 기다리지 않게).
- 예전 v1 의 "96 이상이면 조기 종료"·"가장 높은 힌트 하나만 공개"·"온도는 출제자만"·"힌트 0개면 차례 끝"은 없어졌다.

### 3.3 추리 (`GUESS`)

- 추리자마다 답 **1개**(`SUBMIT_GUESS`). 빈 답은 패스다. 한 번 내면 바꿀 수 없다.
- 30초 **[수치]** 고정. 살아 있는 사람 추리자가 모두 내면 바로 끝난다(봇은 그때 같이 낸다 — §11).
- 내는 동안 남의 답은 아무도 못 본다 — 공개되는 것은 "좌석 N 이 냈다"뿐이다. 끝나면 **모두의 답을 동시에 공개**한다.
- 시간 안에 안 낸 사람은 패스로 친다.

### 3.4 차수 결과와 다음

| 결과 | 추리자 | 출제자 | 다음 |
| --- | --- | --- | --- |
| 한 명 이상 정답 | 맞힌 사람마다 **+1 × r** | 이번 차수 점수 없음 | 출제 차례 끝(`TURN_END`) |
| 전원 오답·패스, 이 차수가 **기준을 넘김** | 0 | **+a × r** (a = 차수 1~5) | 1~4차면 다음 차수, 5차면 차례 끝 |
| 전원 오답·패스, 이 차수가 **기준을 못 넘김**(힌트 0개 포함) | 0 | **0** | 위와 같음(진행은 계속) |

- r = 라운드 번호(1라운드 ×1, 2라운드 ×2, 3라운드 ×3).
- **차수별 기준 온도** **[수치]**(D-320): 1차 **70** · 2차 **75** · 3차 **80** · 4차 **85** · 5차 **88**(`WordTempTuning.DEFAULT` 한 곳 — 처음 정한 90 에서 관제가 88 로 조정, 아래·§15).
  그 차수에 낸 힌트 가운데 가장 높은 온도가 기준 이상이면 "넘김"이다(넘기는 힌트가 나오는 순간 단계가 끝나므로 넘긴 힌트는 차수에 하나다).
- 출제자 점수는 **차수마다 받아 쌓인다** — 2차에 누가 맞혀도 1차에 받은 +1 은 그대로다.
- 5차 기준을 90 → 88 로 낮췄다(사용자가 "90 이 너무 높으면 조정"을 맡김). 90 은 진짜 표에서 90° 이상 쌍이 없는 정답이 324개 중 112개 — 표 밖 낱말의 실시간 채점으로는 넘길 수 있다). 대안 값과 도달률은 §15.

## 4. 점수 표

4인 판 예(추리자 3명), 라운드 r:

| 상황 | 출제자 | 맞힌 추리자 |
| --- | --- | --- |
| 1차에 2명 정답 | 0 | 각 +1r (합 2r) |
| 1차 기준 넘김(72°)·전원 오답 → 2차 1명 정답 | +1r | +1r |
| 1~5차 모두 기준 넘김·전원 오답 | +1r +2r +3r +4r +5r = **+15r** (한 차례 최대) | 0 |
| 1차 기준 못 넘김(최고 58°)·전원 오답 → 2차 기준 넘김(76°)·전원 오답 → 3차 정답 | 0 + 2r | +1r |
| 1차 힌트 0개로 시간 끝 → 추리(전원 패스) → 2차… | 0 (1차) | — |

- 한 출제 차례에서 출제자 최대 15r, 추리자 최대 1r. 판 최고점(4인·보통): 출제 15+30 = 45, 추리 (1+2)×3 = 9 → 54.
- 힌트가 전부 공개되므로 출제자의 줄타기는 "기준은 넘기되, 넘기는 그 힌트와 앞서 낸 힌트들로 정답이 떠오르지 않게"다.

## 5. 입력 검증

### 5.1 낱말 정규화 (힌트·추리 공통)

1. 유니코드 **NFC**(iOS 등에서 오는 NFD 를 합친다).
2. 앞뒤·가운데 **공백 제거**, 문장부호(`.,!?~…·'"` 등) 제거.
3. 남은 글자가 **완성형 한글 음절(가–힣) 1~10자**여야 한다. 자모만(ㄱ·ㅏ)·영문·숫자·이모지가 섞이면 거절.

### 5.2 힌트 거절 (출제자 본인 큐 `ERROR` — 개수는 줄지 않는다)

| 코드 | 사유 |
| --- | --- |
| `NOT_YOUR_PHASE` | 지금 힌트 단계가 아니거나 출제자가 아님, 또는 `turnNo`·`attempt` 가 지금과 다름(늦게 도착) |
| `HINT_FORMAT` | §5.1 에 안 맞음 |
| `HINT_IS_ANSWER` | 정답 또는 그 같은 말과 같거나, 그것을 **포함한다**(정답 수영 → 수영장 ✗) |
| `HINT_INSIDE_ANSWER` | **2자 이상**인 힌트가 정답(또는 같은 말) 안에 들어 있다(정답 눈사람 → 사람 ✗). **1자 힌트는 허용**(눈 ○) **[결정]** |
| `HINT_DUPLICATE` | 이 출제 차례에서 이미 낸 힌트(무효가 된 것은 다시 낼 수 있다) |
| `HINT_LIMIT` | 이번 차수 10개를 다 냄 |
| `SCORING_IN_PROGRESS` | 앞 힌트가 아직 채점 중(한 번에 하나만 — §6.2) |
| `UNKNOWN_WORD` | 표에 없는 낱말인데 실시간 채점이 꺼져 있거나 상한에 닿음(§6.3) — "아직 모르는 낱말이에요" |
| `NO_HINTS_YET` | 힌트 0개에서 [그만 내기] |

채점 결과로 무효가 되는 경우(명사 아님·시간 초과)는 거절이 아니라 비공개 이벤트 `HINT_VOID` 로 온다(§6.2) — 개수는 돌려준다.

### 5.3 추리 거절

| 코드 | 사유 |
| --- | --- |
| `NOT_YOUR_PHASE` | 추리 단계가 아님·출제자임·빠진 좌석·`turnNo`·`attempt` 불일치 |

## 6. 온도 채점

정본 결정은 D-312, 경로의 세부는 설계서 §4·§5. 룰로서 지킬 것만 적는다.

### 6.1 표에 있는 힌트 — 바로

서버는 부팅 때 읽어 둔 **유사도 표**에서 (정답, 힌트)를 찾는다. 있으면 그 값이 온도이고 `SUBMIT_HINT` 의 응답으로 출제자에게 바로 간다.

### 6.2 표에 없는 힌트 — 채점 중 → 반영

1. 힌트는 **채점 중**(`PENDING`)으로 상태에 들어가고 개수 한 칸을 차지한다. 출제자에게 `HINT_PENDING`.
2. 방 잠금 밖의 채점기가 Claude 에 묻는다. 답은 `{isValidNoun, similarityScore, reason}`.
3. 엔진 타이머가 결과를 반영한다(보통 2~3초 **[수치]** — 그 동안 출제자 화면은 "채점 중…"):
   - 명사이고 점수가 왔다 → 온도 확정(`HINT_SCORED` — 모두에게). 기준 온도 이상이면 §3.2 대로 단계가 끝난다.
   - 명사가 아니다 → **무효**(`HINT_VOID{reason: NOT_A_NOUN}`), 개수를 돌려준다.
   - 8초 **[수치]** 안에 답이 없거나 실패·거절 → **무효**(`HINT_VOID{reason: SCORING_FAILED}`), 개수를 돌려준다.
- 채점 중에는 새 힌트·[힌트 끝]을 받지 않는다(한 번에 하나). 화면은 입력란을 잠근다.
- **힌트 제한이 끝났는데 채점 중**이면 결과(또는 8초)를 기다렸다가 단계를 끝낸다 — 새 힌트는 더 받지 않는다.

### 6.3 같은 쌍은 같은 온도

- 한 번 매긴 (정답, 힌트) 점수는 서버가 저장해 두고 다시 묻지 않는다(표 → 저장된 실시간 점수 → 새로 묻기 순).
- **확정된 온도는 매치 상태에 들어간다.** resync·결과 화면·기록은 상태의 값을 읽고 다시 채점하지 않는다.
- 표가 판 도중 새 버전으로 바뀌어도(재배포) 이미 매긴 힌트는 그대로, 새 힌트만 새 표로 매긴다 **[결정]**.
- 실시간 채점이 꺼져 있거나 하루·판 상한에 닿으면 표 밖 힌트는 `UNKNOWN_WORD` 로 거절한다(개수 유지). 게임은 표만으로 계속된다.
- 힌트가 여러 뜻을 가진 낱말이면 **정답에 가장 가까운 뜻**으로 매긴다(표·실시간 같은 기준).

## 7. 정답 판정

판정은 서버가 한다. 추리 답 g, 정답 집합 A = {정답 낱말} ∪ 같은 말 목록.

1. g 를 §5.1 로 정규화한다. A 의 낱말도 같은 정규화를 거친 값으로 견준다.
2. g ∈ A 면 정답.
3. 아니면 g 의 끝에서 **끝말 하나**를 뗀 값이 A 에 있으면 정답. 끝말 목록 **[결정]**: `요`·`다`·`이다`·`임`·`입니다`·`이요`·`예요`·`이에요`.
   (뗀 뒤 1자 이상 남을 때만. 두 번 떼지 않는다.)
4. 그 밖은 오답. **오타·한 글자 차이는 인정하지 않는다.**

| 정답 | 추리 | 판정 | 이유 |
| --- | --- | --- | --- |
| 사과 | `사과` · ` 사 과 ` · `사과!` | ○ | 정규화 |
| 사과 | `사과요` · `사과입니다` | ○ | 끝말 떼기 |
| 휴대폰 | `핸드폰` | ○ | 같은 말 목록 |
| 케이크 | `케익` | ○ | 표기 변형 목록(은행에 있을 때만) |
| 사과 | `사가` · `사괴` | ✗ | 오타 |
| 사과 | `풋사과` · `사과나무` | ✗ | 다른 낱말 |
| 바다 | `바다다` | ○ | 끝말 `다` |
| 수다 | `수` | ✗ | 정답 쪽은 떼지 않는다 |
| 사과 | `apple` | 거절 | `GUESS_FORMAT` |

- 표기 변형·같은 말은 **은행에 적힌 것만** 인정한다. 억울한 사례는 은행 목록을 고쳐 푼다(판정 규칙을 넓히지 않는다).
- **정답 은행의 조건**: 흔하고 구체적인 명사, 2~6자, **뜻이 하나로 읽히는 낱말만**(배·눈·다리·차·말·밤·김 같은 동음이의어는 정답에서 뺀다 —
  힌트로는 쓸 수 있다). 낱말마다 범주·뜻풀이 한 줄·같은 말 목록을 둔다. 끝말 목록의 글자로 끝나 판정이 헷갈리는 낱말(수다·바다 등)은
  S1 에서 사례를 테스트로 고정하고, 문제가 되면 은행에서 뺀다.

## 8. 순위·끝

- 판은 마지막 라운드의 마지막 출제 차례가 끝나면 끝난다(`FINISHED`).
- 순위: **총점** 높은 순 → 같으면 **공동 순위**(1, 1, 3 식). 추가 동점 규칙은 두지 않는다 **[결정]**.
- 빠진 사람(탈주·강퇴)은 점수와 무관하게 모두 같은 최하위.
- 빠진 사람 없이 **모두 같은 점수**면 무승부(`recordDraw` — ELO 변화 없음, 참가 점수는 받는다).
- 끝난 이유(`endReason`): `FINISHED` · `LAST_SEAT`(살아 있는 좌석 1) · `NO_HUMANS`(살아 있는 사람 0).

## 9. 시간

| 단계 | 길이 | 일찍 끝남 | 시간이 다 되면 |
| --- | --- | --- | --- |
| `WORD_SELECT` | 20초 | 살아 있는 사람이 모두 고름 | 안 고른 좌석은 무작위 |
| `HINT` | 힌트 제한 T(60·90·120·180, 기본 90) | 기준 온도 이상인 힌트 · 10개 다 냄 · [그만 내기] | 추리로 간다(기준 못 넘김 — 힌트 0개여도). 채점 중이면 최대 8초 더 |
| `GUESS` | 30초 | 사람 추리자가 모두 냄 | 안 낸 좌석은 패스 |
| `ATTEMPT_RESULT` | 5초 | — | 다음 차수(5차까지) 또는 `TURN_END` |
| `TURN_END` | 6초 | — | 다음 출제자·라운드·판 끝 |

- 전부 **엔진 타이머**(포트 ⑦)다. 단계 시작 시각이 상태에 있어 재무장해도 처음부터 다시 세지 않는다(D-183 방식).
- 인프라 턴 데드라인(마지막 액션 + T)은 늘 단계 마감보다 늦거나 같다. 그쪽 `timeoutAction` 은 `TICK{turnNo, attempt, phase}` —
  "지금 단계가 그 단계이고 마감이 지났을 때만" 엔진 타이머와 **같은 전이**를 하고, 아니면 아무것도 바꾸지 않는다(멱등 — 힌트를 낼 때마다
  밀려 다시 걸린 데드라인이 다음 단계에서 발화해도 해가 없다). 클라가 `TICK` 을 위조해 보내도 이미 지난 마감을 처리할 뿐이다.
- 화면의 남은 시간은 공개 뷰의 `phaseRemainingMs`(엔진 계산)를 쓴다 — resync 바깥값 `turnRemainingMs` 는 이 게임에서 단계 시간과 다르다(요트와 같다).
- 판 길이 어림(D-320 시뮬레이션 — 진짜 표·사람 모형, 평균/90%): 4인 보통 약 19분/24분, 6인 보통 약 23분/30분, 6인 길게 약 35분/43분(최대 61분). 짧게는 절반. 출제 차례당 평균 1.9~2.8차수.

## 10. 탈주·강퇴

- 판은 계속된다(`MATCH_CONTINUES`). 빠진 좌석은 `SEAT_OUT` 으로 알리고, 그 뒤 출제 차례·추리에서 건너뛴다. 좌석 번호는 그대로다(D-122).
- **출제 중**(그 사람의 `HINT`·`GUESS`·`ATTEMPT_RESULT`)에 빠지면: 그 출제 차례를 **그 자리에서 끝내고** `TURN_END` 로 간다(정답 공개).
  진행 중이던 차수의 점수는 아무도 받지 않는다. 앞 차수에서 이미 받은 점수(출제자·추리자 모두)는 유지 — 빠진 사람은 어차피 최하위다.
  채점 중이던 힌트는 버린다.
- **추리 중** 빠지면: 그 좌석은 패스로 치고, 남은 사람이 모두 냈으면 바로 마감.
- `WORD_SELECT` 중 빠지면: 고를 필요가 없어진다.
- 방장 강퇴(D-162, 끊긴 사람만)·끊김 유예 만료도 같은 `desert` 경로다. 이미 빠진 좌석의 재요청은 `NOT_APPLICABLE`.
- 살아 있는 좌석이 **1명**이 되면 판 끝(`LAST_SEAT`), 살아 있는 **사람이 0명**이면 판 끝(`NO_HUMANS`). 2명이면 1:1 로 계속한다.

## 11. 봇 (`BOT_LEVEL`)

봇은 **표 안의 낱말만** 쓴다(실시간 채점 호출 0). 봇이 아는 것은 공개 정보와 유사도 표뿐이고, 사람은 정답 은행을 모르므로 강도를 단계마다 눌러 둔다.

| | 쉬움 `EASY` | 보통 `NORMAL` | 어려움 `HARD` |
| --- | --- | --- | --- |
| 출제 — 기준을 넘기는 힌트 앞에 내는 낮은 힌트 | 2~3개 | 1~2개 | 0~1개 |
| 추리 — 아는 은행 | 은행의 30% (정답 포함 여부도 운) | 60% | 100% |
| 추리 — 온도 읽기 잡음 | ±15 | ±8 | ±3 |
| 추리 — 차수당 맞힐 확률 상한 | 6% | 14% | 25% |

- 수치는 전부 **[수치]**(D-320 에서 다시 정함 — v1 은 10·30·50%). 힌트가 전부 공개되고 차수가 5번이라 상한을 낮췄다: 한 출제 차례에 맞힐
  확률은 차수마다 쌓인다. 시뮬레이션의 봇 적중률(차수당 / 출제 차례 누적, 3~6인): 쉬움 약 2% / 4~7%, 보통 약 8% / 16~26%, 어려움 약 25% / 39~60%.
- **출제 봇**: 낮은 힌트 몇 개(기준−30° ~ 기준−1°) 뒤에 **기준 ~ 기준+5°** 의 힌트 하나를 내 통과한다. 그 띠가 비면 기준 이상 중 가장 낮은 것,
  표에 기준 이상이 없으면 아는 것 중 가장 높은 것을 내고 그만둔다(그 차수는 기준 못 넘김). 표 밖 낱말(실시간 채점)은 쓰지 않는다.
  진짜 표에서 봇이 기준을 넘기는 정답 수(1~5차): 324 / 324 / 323 / 281 / 167.
- **추리 봇**: 공개된 **모든** 힌트·온도와 표가 맞는 정답 후보를 (아는 은행 안에서) 거꾸로 찾아 가장 그럴듯한 것을 낸다. 상한 확률에 걸리면
  두 번째 후보나 패스를 낸다. 이미 틀린 답은 다시 내지 않는다.
- **속도**: 봇의 행동 시각은 상태에 두고 **엔진 타이머**가 실행한다(인프라 봇 루프 아님 — `pendingSeats` 에 봇을 넣지 않는다).
  힌트 사이 4~9초, 추리는 5~20초 뒤 **[수치]**. 사람 추리자가 모두 내면 봇도 그 자리에서 낸다(사람을 기다리게 하지 않는다).
  사람이 없는 단계(전원 봇)는 짧은 간격으로 흘러간다.
- 정책이 예외·비합법 수를 내면 ERROR 로그 뒤 그 좌석은 패스·[힌트 끝]·무작위 고르기로 넘어간다(D-118·D-119).

## 12. 공개·비공개 — 누가 언제 무엇을 보나

판정은 상태 함수 한 곳(예정 `WordTempVisibility`)에 모은다. 공개 뷰·공개 이벤트 **타입에 비밀 필드 자체가 없다**(직렬화 테스트로 고정).

| 정보 | 출제자 | 추리자 | 관전자 | 언제 모두에게 |
| --- | --- | --- | --- | --- |
| 내 후보 낱말·내가 고른 낱말 | 본인만 | 본인만(자기 것) | ✗ | 고른 낱말은 그 출제 차례의 `TURN_END`. 안 쓴 후보는 **끝까지 비공개** |
| 이번 정답 낱말 | ○ | ✗ | ✗ | `TURN_END` |
| 낸 힌트의 낱말·온도·채점 중 표시(이 출제 차례 전부) | ○ | ○ | ○ | **낼 때마다 바로**(D-320 — 비밀이 아니다) |
| 힌트 개수("3/10")·차수의 기준 온도·넘겼는지 | ○ | ○ | ○ | 실시간 |
| 누가 추리를 냈는지 | ○ | ○ | ○ | 실시간(내용 없음) |
| 추리 답의 내용 | ✗ | 자기 것만 | ✗ | 추리 단계가 끝날 때 동시에 |
| 점수·순위·단계·남은 시간 | ○ | ○ | ○ | 실시간 |

- **오답도 낱말 그대로 공개**한다(무엇을 떠올렸는지가 재미다). 다만 작은 **금칙어 목록**에 걸리는 답은 남에게 `···` 로 가려 보인다
  (본인에게는 그대로) **[결정]**. 방 채팅이 이미 필터 없이 열려 있어 그 이상은 하지 않는다(신고는 채팅 신고와 같다).
- 늦게 들어온 resync·관전 입장도 같은 함수를 거친다 — 추리 단계 중에는 답이 어디에도 없다.
- 봇·빠진 좌석·관전자에게는 비공개 정보를 보내지 않는다.
- **채팅은 막지 않는다.** 방 채팅·좌석 위 채팅 줄로 정답이나 답을 알려 주는 것은 **하지 않기로 하는 규칙**이다(튜토리얼 한 줄:
  "채팅으로 정답을 알려 주면 재미가 없어요"). 기술로 막으려면 인프라를 고쳐야 해서 v1 에서는 하지 않는다.
- **공개 저장소**: 정답 은행·유사도 표는 저장소 자원이라 누구나 볼 수 있다. 친구끼리 하는 게임이라 v1 에서는 감수한다 **[결정]**.

### 12.3 비공개 이벤트 (`/user/queue/room/{roomId}`) — 전부 순번 없음(D-126)

| 이벤트 | 받는 사람 | 실리는 것 |
| --- | --- | --- |
| `WORD_CANDIDATES` | 각자 | 내 후보(낱말·범주 이름·뜻풀이), 이번 라운드에 고를 수 있는 것 |
| `GUESS_ACCEPTED` | 낸 추리자 | 내가 낸 답 |
| `ERROR` | 본인 | §5 의 코드 |

판 시작 때는 상태를 저장한 **뒤에** 공개 `WORD_SELECT_STARTED` 하나만 보낸다(D-319 — 첫 resync 가 저장보다 빨랐던 클라가 이것을 받고 다시 받는다). 1라운드의 내 후보는 resync 의 비공개 뷰로 받고, `WORD_CANDIDATES` 는 2라운드부터 온다(D-316).

비공개 뷰(`privateView`)는 같은 내용을 통째로 준다 — 내 후보·고른 낱말, (출제자면) 이번 정답, (추리자면) 이번 차수에 낸 내 답. 힌트는 공개 뷰 `hints` 에 있다(D-320).

## 13. 기록

- 매치 결과는 V25 의 `word_temp_match_results`·`word_temp_match_participants` 에 남긴다(순위·총점·출제 점수·추리 점수·승·탈주).
  결과 요약(payload)에는 출제 차례별 **정답 낱말·공개된 힌트·온도·맞힌 좌석**만 싣는다 — 오답 원문은 남기지 않는다.
- 전적·레이팅은 다른 개인전과 같다: `RatedMatchPolicy.eloFactor` → `UserGameStatsService.ratingInput` → `EloCalculator.freeForAllDeltas` →
  `record`/`recordDraw`. 승 = 공동 1위 전원. 일부만 동점인 판의 증감은 S2 기록기 테스트로 고정한다.
- 참가 점수(D-301)는 판 길이와 무관하게 그대로 준다 **[결정]** — 짧게 판을 돌려 올리는 일이 보이면 S4 뒤에 다시 본다.
- 표 밖 힌트의 실시간 점수는 `word_temp_live_scores` 에 **낱말과 횟수만** 남는다(사용자·방 식별자 없음 — 설계서 §6). 다음 표 갱신 재료다.

## 14. 예시 — 한 출제 차례 (4인, 1라운드, 힌트 제한 90초, D-320)

정답 **바다**(출제자 가람). 추리자 나래·다온·라온. 기준 온도 70 · 75 · 80 · 85 · 88.

1. **1차 힌트**(기준 70): 가람이 `여름` → 모두에게 **여름 58°**. 이어서 `갈매기` → **갈매기 71°** — 기준을 넘겨 그 자리에서 추리로("기준 70° 넘김 → 추리").
2. **1차 추리**: 나래 `항구`, 다온 `해변`, 라온 패스 → 동시 공개, 전원 오답. 가람 **+1**(1차 × 1라운드).
3. **2차 힌트**(기준 75): `짠맛`(표에 없음 → 모두에게 "채점 중" 2초 → 64°), `소금`(62°)… 시간이 끝나도록 75 를 못 넘겼다 →
   "기준 못 넘김 — 맞히는 사람이 없어도 이번 차수 점수 없음", 그래도 추리로.
4. **2차 추리**: 전원 오답 → 가람은 2차 점수 **0**(1차의 +1 은 유지). 3차로.
5. **3차 힌트**(기준 80): `항구`(80°) → 통과. **3차 추리**: 나래 `바다요`(끝말 떼기 → 정답), 라온 `바다` → 나래·라온 **+1 씩**. 가람은 3차 점수 없음.
6. **차례 끝**: 정답 바다 공개 6초 → 다음 출제자. 화면에는 1~3차의 힌트(여름 58°·갈매기 71°·짠맛 64°·소금 62°·항구 80°)가 차수별로 남아 있다.

## 16. 범위 밖 (v1)

- 방송의 추가 추리 장치(한 차수에 답을 더 내는 것), 팀전, 2인 판, 7인 이상.

- 영어·숫자·문장 힌트, 오타 인정, 채팅 필터.
- 정답 은행 비공개 주입, 실시간 채점 결과의 사람 검수 화면(어드민) — 필요해지면 후속.

## 17. 검증 기준 (S1 에서 채움)

- 엔진 불변식(D-320): 점수 합 = 이벤트의 증감 합, 한 차례 출제자 ≤ 15r·추리자 ≤ 1r, 차수 ≤ 5, 차수당 확정+채점 중 힌트 ≤ 10, 차수에 기준 이상 힌트 ≤ 1,
  출제자 차수 점수 = (전원 오답이고 기준 넘김 ? 차수×r : 0), 공개 뷰 JSON 에 정답·미공개 추리 문자열 없음(모든 단계에서), 안 쓴 후보는 어떤 공개 출력에도 없음.
- 시뮬레이션: 3~6인 × 판 길이 3종 각 2,000판 완주(무한 루프·예외 0), 판 길이·점수 분포 통계 파일.

- 타이머: 같은 상태에서 `TICK` 과 `onTimer` 가 같은 결과, 낡은 `TICK` 은 무변경.
