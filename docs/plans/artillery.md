## 0. 한 줄 요약

하늘에 뜬 흙섬 정원에서 화분 포대가 씨앗을 쏴 서로를 구름 바다로 떨어뜨리는 2~6인 턴제 포격 게임.
**물리는 서버가 정수(고정 소수점)로 한 발에 한 번만 계산**하고, 클라는 받은 궤적·충돌·지형 변화를 재생만 한다.
포트 확장 없이 붙는다 — 발사 뒤 연출 대기는 원카드가 넣은 **엔진 타이머(D-128)** 를 그대로 쓴다.

## 2. 세계관과 이름 (독창 요소)

- **무대 — 하늘 정원**: 구름 바다 위에 흙섬 몇 개가 떠 있다. 섬은 흙 덩어리라 씨앗이 터지면 패이고, 섬 아래는
  구름 바다다. **떨어지면 탈락**.
- **포대 — 화분 포대**: 각자 화분에 심은 포대 식물을 키운다. 포신은 줄기, 탄은 씨앗.
- **서든데스 — 구름 밀물**: 판이 길어지면 구름 바다가 차올라 낮은 땅부터 삼킨다(판 길이 상한 장치, §3.7).
- 화면 이름은 가제 "씨앗포". 코드 이름은 장르 이름으로 둔다(이름이 바뀌어도 패키지를 안 바꾸게):
  패키지 `domain.game.artillery`, 게임 ID `ARTILLERY`, CSS 접두 `.ar-`.

## 3. 핵심 룰 (v1 기준선 — 정본은 S0 의 `docs/rules-artillery.md`)

### 3.1 인원·좌석·시작

- 2~6인, 기본 4. MVP 는 **개인전**(팀전은 후속 S7 — §3.8).
- 맵은 매치 시드로 생성한다(§4.3). 출발 자리는 맵이 만든 N개 자리에 **시드로 섞어** 앉힌다(좌석 순서와 무관 —
  좌석 0 이 늘 왼쪽 끝인 불공정 제거).
- 첫 차례도 시드로 고른다. 이후 차례는 좌석 순서(+1, D-132 와 같은 방향)로 돌고 탈락자는 건너뛴다.

### 3.2 한 차례

1. 차례 시작: 바람이 새로 정해진다(−10~+10 정수, 시드), 이동 연료가 가득 찬다.
2. 이동(선택): 지면을 따라 좌우로 걷는다. 1칸에 연료 1, 오르막 한 칸 높이당 +1. 한 걸음에 오를 수 있는 높이는 3칸(그 이상은 벽).
3. 조준: 각도(0~180°, 1° 단위) · 힘(0~100, 1 단위) · 탄을 고른다.
4. 발사 → 해소(궤적·폭발·피해·낙하) → 연출 시간이 지나면 다음 차례.
- **이동과 발사는 한 액션 `FIRE` 로 보낸다**(§6.2 — 이동 거리를 함께 실어 보냄). 차례 중 서버로 가는 액션은 한 번뿐이다.
- 차례를 넘길 수 있다(`SKIP`). 시간 초과도 넘김과 같다(이동 없음).

### 3.3 탄도와 바람

- 중력은 아래로 일정, 바람은 매 틱 가로 가속(유닛·탄별 바람 영향 배율). 공기 저항 없음.
- 탄은 지형·포대에 닿거나, 좌우·아래 경계를 벗어나면 끝난다. **위쪽 경계는 열려 있다**(높이 쏴도 돌아온다).
- 최대 비행 15초(900틱) — 넘으면 그 자리에서 소멸(피해 없음).

### 3.4 폭발·피해·지형

- 충돌점 중심 원을 지형에서 지운다(구멍). 섬은 떠 있으므로 흙은 떨어지지 않는다(낙사는 포대만).
- 피해: 폭발 반경 R 안의 포대마다 `최대 피해 × (R − 거리) / R`(정수 나눗셈), 직격은 최대 피해. **자기 피해 있음.**
- 낙하: 발밑 땅이 사라진 포대는 떨어진다. 20칸 넘게 떨어지면 넘은 칸 2칸당 1 피해. 구름 바다(맵 아래 또는 구름 수면 아래)에 닿으면 탈락.
- 해소 순서는 고정: 구멍 전부 → 폭발 피해(좌석 순) → 낙하(좌석 순) → 탈락 판정. 같은 해소에서 동시에 0 이하가 된 포대는 동시 탈락.

### 3.5 체력·탈락

- 체력 0 이하 또는 구름 바다에 닿으면 탈락. 탈락한 포대는 맵에서 시들어 사라진다(지형 변화 없음).
- 탈주(D-75 유예 180s 뒤 확정)도 탈락으로 처리하고 판은 남은 사람끼리 계속한다(`MATCH_CONTINUES`, 스컬킹 D-104 와 같은 갈래).

### 3.6 종료·순위

- 살아 있는 포대가 1개 이하가 되면 종료. 1등은 마지막까지 남은 포대.
- 나머지는 **늦게 탈락한 순**. 같은 해소에서 함께 탈락하면 탈락 직전 체력이 높은 쪽이 위, 그것도 같으면 동순위. 탈주자는 최하위.
- 살아 있는 사람이 없으면(봇만 남음) 그 자리에서 종료(원카드 `NO_HUMANS` 와 같은 처리).

### 3.7 구름 밀물 (판 길이 상한)

- 전원이 한 바퀴 도는 것을 1라운드로 센다. **10라운드가 끝나면** 매 차례 시작 때 구름 수면이 15칸씩 오른다.
- 수면은 맵 꼭대기까지 오르므로 판은 반드시 끝난다. 상한: 10라운드 + 360/15 = 24차례.
  불변식 테스트가 이 상한을 고정한다(원카드의 "총 차례 상한" 안전장치와 같은 역할).

### 3.8 팀전 (후속 S7 — 설계만)

- `RoomOption.TEAMS` 를 선언하면 대기실 라벨이 "팀 배정"이 된다(D-106). 팀은 좌석 홀짝(2팀) — 4인 2:2, 6인 3:3.
  `teamPolicy` 가 좌석 순서를 정하므로 좌석 홀짝 = 팀이 되고 차례가 팀을 번갈아 돈다.
- 아군 피해 있음(장르 관례). 종료는 한 팀만 남을 때. 순위는 팀 단위(승/패).
- `GameContext` 에 팀 정보가 없어도 된다 — 티츄처럼 좌석에서 유도한다.

## 4. 서버 권위와 물리

### 4.1 원칙

- **서버가 한 발에 한 번 계산하고 결과를 보낸다.** 서버에 실시간 물리 루프(틱마다 도는 시뮬레이션)는 없다.
  계산은 `FIRE` 액션을 적용하는 순간 수 ms 안에 끝나고, 결과는 "재생 대본"(궤적 점열·충돌점·구멍·피해·낙하 경로)이다.
- 클라는 대본을 시간축에 맞춰 그릴 뿐 **물리를 계산하지 않는다**(Server-Authoritative). 조준 중 궤적 미리보기도 없다
  (장르 재미이기도 하고, 미리보기를 주려면 클라에 물리를 복제해야 한다).
- 예외 하나: **이동 미리보기**는 클라가 걷기 규칙(§3.2-2)을 흉내 내 보여 준다. 서버가 같은 규칙으로 다시 걸어 보고
  실제 도착점을 대본에 싣는다 — 어긋나도 서버 값이 이긴다(§6.2).

### 4.2 고정 소수점 (결정성)

Java 는 17부터 부동소수점도 엄격(strictfp)이라 같은 JVM 에서는 결정적이지만, **정수로 하면 언어·인스턴스·테스트 어디서나
같은 비트가 보장되고 더 싸다.** 그래서 전부 정수다.

| 항목 | 표현 |
| --- | --- |
| 좌표 | 칸 단위 × 256 (Q8, `int`). 맵 640×360칸이면 최대 163,840 — `int` 여유 |
| 속도·가속 | 틱당 Q8. 틱은 1/60초(재생 기준 시간) |
| 삼각함수 | 0~180° 의 `sin`/`cos` × 65536 정수 표(181개 상수를 소스에 박는다 — 런타임 `Math` 호출 없음) |
| 적분 | 반암시 오일러: `vx += 바람가속; vy += 중력; x += vx; y += vy` (정수 덧셈만) |
| 충돌 | 틱마다 이동 선분을 1칸 이하 보폭으로 쪼개 지형 비트·포대 원(반경 6칸)과 대조 |
| 거리 | 제곱 거리 정수 비교, 피해 계산만 정수 제곱근(`isqrt`) |
| 난수 | **자체 SplitMix64**(몇 줄 — JDK 구현 변화와 무관). 맵 생성·바람·봇 오차만 쓴다 |

- **시드**: 매치 시작 때 `SecureRandom` 으로 64비트 시드를 뽑아 상태에 둔다. 바람은 `f(시드, 차례 번호)`, 맵은 `f(시드)`.
  시드는 **공개 뷰에 싣지 않는다** — 알면 앞으로의 바람을 미리 계산할 수 있다.
- 결정성이 주는 것: (1) 골든 테스트, (2) 봇이 보는 결과 = 실제 결과, (3) 어느 인스턴스가 처리해도 같은 결과(수평 확장 D 트랙),
  (4) 버그 리포트를 시드 + 액션 열로 재현.

### 4.3 지형 표현

- **비트 마스크** 640×360칸(230,400비트 = 28.8KB). 높이맵이 아니라 비트라서 구멍 아래 동굴·처마가 생긴다(장르의 맛).
- **상태에는 비트를 저장하지 않는다**: `(시드, 지형 연산 목록)` 만 저장하고, 비트는 시드로 만든 원본에 연산(원 지우기·후속의
  둔덕 쌓기)을 차례로 적용해 얻는다. 상태 JSON 이 수백 바이트~수 KB 로 작게 유지된다(Redis `room:{id}:state` 패턴 그대로).
- 재구성 비용은 맵 생성(23만 칸) + 연산 수십 개 × 원 1,800칸 ≈ 30만 번의 비트 연산 — 수 ms. 어댑터가 `(roomId, 연산 수)` 로
  마지막 비트 1개를 메모리에 들고 있으면 대부분 재구성도 없다(캐시가 틀려도 다시 만들면 되므로 정합성 문제 없음).
- **맵 생성**: 정수 값 노이즈로 흙섬 2~4개를 만들고 **좌우 대칭**으로 맞춘다(출발 자리 공평). 출발 자리는 섬 윗면에서
  일정 간격 이상 떨어진 평평한 곳 N개. 생성 실패(자리가 모자람)면 시드를 이어 다시 뽑는다 — 결정적.
- **클라 전달**: resync 공개 뷰에 열 단위 런 길이 부호(열마다 "흙 구간의 시작·끝" 목록, 수 KB)로 싣는다. 이후에는 이벤트의
  구멍 목록만 받아 클라가 직접 지운다(정수 원 지우기 — 같은 식이라 어긋날 일이 거의 없고, 어긋나도 다음 resync 가 고친다).

### 4.4 한 발의 해소 (서버)

```
FIRE(moveDx, angle, power, shell)
 ├ 검증: 내 차례·AIMING 단계·범위·탄 수량
 ├ 이동: 걷기 규칙으로 moveDx 만큼(연료·벽에서 멈춤) → 실제 도착점·경로
 ├ 탄도: 포구 위치에서 정수 적분, 충돌·경계·900틱까지
 ├ 폭발: 구멍 연산 추가 → 피해 → 낙하(포대별 경로) → 탈락
 ├ 대본: 이동 경로 + 궤적(2틱마다 1점) + 충돌점 + 구멍 + 피해 + 낙하 경로 + 탈락 + 연출 길이(ms)
 └ 상태: 결과를 **즉시 반영**하고 단계 = RESOLVING, 연출 끝 시각 기록, pendingSeats = []
엔진 타이머(D-128): RESOLVING 의 남은 연출 시간 → 만료 시 onTimer → 다음 차례(바람·밀물·TURN_CHANGED)
```

- 상태는 발사 순간 이미 결과다. 연출 대기는 "다음 차례를 언제 열지"만 정한다 — 그 사이 resync 하면 결과 상태를 받는다.
- 연출 길이 = 이동 틱 + 비행 틱 + 폭발 0.6초 + 낙하 틱을 1/60초로 환산, 상한 18초.

### 4.5 무료 서버 CPU·메모리 추정

운영 머신 shared-cpu-1x / 512MB, C1 JIT 만(D-158) — C2 보다 2~3배 느리다고 잡는다.

| 작업 | 연산량 | 추정(C1) |
| --- | --- | --- |
| 한 발 탄도 | ≤900틱 × 보폭 ≤4 = 3,600회 비트 조회 | < 0.2ms |
| 구멍·피해·낙하 | 원 ≤1,800칸 + 포대 6 × 낙하 ≤360칸 | < 0.5ms |
| 지형 재구성(캐시 미스) | ~30만 비트 연산 | 2~5ms |
| **한 발 합계** | | **≤ 6ms** |
| 봇 한 수(§7) | 탄도 시뮬 ≤800회 + 재구성 1회 | 50~150ms(예산 200ms에서 끊음) |
| 메모리 | 방마다 캐시 비트 28.8KB | 방 100개 3MB |

- 부하 모델: 방 하나에 발사는 차례 길이(조준 10~30초 + 연출 3~8초)마다 1번 → **방당 분당 2~4발**. 동시 20방이어도
  초당 1발 남짓 = CPU 1% 미만. 상시 도는 루프가 없으니 빈 방은 0이다.
- 비용이 큰 것은 봇이다. 봇 탐색은 방 액션 락 안에서 돌므로(락 TTL 2초) **시뮬 횟수 상한 + 시간 예산(200ms)** 을 둘 다 건다.
- 네트워크: 대본 한 건 3~6KB(궤적 450점 정수 배열), resync 지형 수 KB. STOMP 프레임 한도 안.
- 결론: 무료 사양으로 충분. 숫자는 S1·S3 벤치로 확인하고 이 표를 실측값으로 바꾼다.

## 5. 포트 적합성

| # | 포트 책임 | 씨앗포 | 비고 |

| 1 | `apply` | `FIRE`·`SKIP` | 발사 순간 전부 해소 |
| 2 | 상태 직렬화 | JSON(시드·연산 목록·포대·차례) | 비트는 저장 안 함(§4.3) |
| 3 | `publicView` | 포대 위치·체력·탄 수·바람·수면·지형 RLE·단계·남은 연출 | |

| 4 | `phaseName` | `AIMING` / `RESOLVING` / `ENDED` | |

| 6' | `botAction` | override(§7) | 정책 실패 시 `timeoutAction` 폴백(포트 권장 패턴) |
| 6'' | `timeoutAction` | `SKIP` | |
| 7 | `timer` / `onTimer` | RESOLVING 남은 연출 시간 → 다음 차례 | **원카드가 넣은 확장 그대로** |
| — | `desert` | 탈락 처리 후 `MATCH_CONTINUES`, 생존 ≤1 이면 `MATCH_ENDED` | 이미 탈락한 좌석은 `NOT_APPLICABLE` |

**포트 변경이 필요 없는 이유와 그 대가**

- 인프라는 액션마다 `onTurnAdvanced` 로 **턴 데드라인을 처음부터 다시 건다**(`TurnTimeoutScheduler`). 이동을 따로 보내는
  `MOVE` 액션을 두면 걸을 때마다 턴 시간이 다시 차서 시간 제한이 무의미해진다.
- 그래서 **이동은 `FIRE` 에 실어 한 번에 보낸다**(§3.2). 대가: 다른 사람에게는 내 이동이 실시간으로 보이지 않고 발사 대본의
  앞부분으로 재생된다. 턴제라 재미 손실은 작다고 본다.
- 후속으로 실시간 이동·조준 공유를 원하면 그때 포트에 **"같은 차례 안의 액션은 턴 시계를 다시 걸지 않는다"** 는 선택형 확장
  (예: `default boolean restartsTurnClock(GameState before, GameState after) { return true; }`)을 검토한다(§11).

**기타 붙는 것(인프라 수정 없음)**

- `GameDefinition`: 2~6인, `defaultPlayers()` 4, `turnSecondsChoices()` 20·30·45·60, `defaultTurnSeconds()` 30(끔 없음 — §11 Q3),
  `supportedRoomOptions()` 빈 집합(MVP) → S7 에서 `TEAMS`.
- 상태 `COMING_SOON` 으로 시작, 공개 전환은 설정 한 줄(D-131·D-168 선례 — `MIRBOARD_ARTILLERY_STATUS`).
- 매치 기록기: 원카드처럼 **순위 기반**(최종 순위로 ELO·전적, `RatedMatchPolicy.eloApplies` 하나로 판정, 비봇마다
  `user_game_stats`, 발행 지점에서 예외 격리 — 포트 "매치 기록기 계약" 1~3). 매치 테이블 마이그레이션 1개(V 번호는 착수 시점 — 다른 기획과 겹칠 수 있다).
- `HeadToHeadSource`: 최종 순위로 센다(원카드와 같음).
- 봇 풀: V10 으로 늘어난 봇 계정을 쓴다. 6인 봇 채우기가 되는지 S3 에서 확인.

## 6. 액션과 이벤트 (STOMP)

### 6.1 목록

| 방향 | type | 내용 |
| --- | --- | --- |
| 클라→서버 | `FIRE` | `moveDx`(부호 있는 칸 수, 0 가능) · `angle` · `power` · `shell` (S6: `item`) |
| 클라→서버 | `SKIP` | 차례 넘김 |
| 공개 | `TURN_CHANGED` | 좌석 · 차례 번호 · 바람 · 구름 수면 · 연료(가득) — 게임 간 type 재사용 |
| 공개 | `SHOT_RESOLVED` | 아래 대본(결과값) |
| 공개 | `TURN_SKIPPED` | 좌석 · 사유(`SKIP`/`TIMEOUT`) |
| 공개 | `UNIT_ELIMINATED` | 좌석 · 사유(`DESERTED`) — 발사로 인한 탈락은 `SHOT_RESOLVED` 안에 |
| 공개 | `MATCH_ENDED` | 순위 · 사유(`LAST_STANDING`/`NO_HUMANS`) |
| 비공개 | `ERROR` | `NOT_YOUR_TURN` · `RESOLVING` · `OUT_OF_RANGE` · `NO_AMMO` (순번 없음 — `sequenced()=false`, D-126) |

- 시작 상태는 원카드처럼 **이벤트 없이 resync** 로 받는다(`MATCH_STARTED` 를 두지 않는다).
- 비공개 손패 같은 것이 없어 비공개 이벤트는 `ERROR` 뿐이다.

### 6.2 `SHOT_RESOLVED` 대본

```json
{ "seat": 2, "angle": 63, "power": 71, "shell": "PUMPKIN", "wind": -4,
  "move":  { "path": [[x,y], ...], "to": [x,y], "fuelLeft": 37 },
  "shots": [ { "path": [x0,y0,x1,y1, ...], "impact": [x,y] | null, "crater": [x,y,r] | null } ],
  "damages": [ { "seat": 1, "amount": 28, "hpAfter": 44, "cause": "BLAST" } ],
  "falls":   [ { "seat": 1, "path": [[x,y], ...], "damage": 6, "hpAfter": 38 } ],
  "eliminated": [ { "seat": 3, "cause": "CLOUD_SEA" } ],
  "units":   [ { "seat": 1, "x": 0, "y": 0, "hp": 38 }, ... ],
  "durationMs": 5400 }
```

- **결과값 원칙**(원카드 §4.3): 피해에 `hpAfter`, 끝에 `units` 전체 스냅샷 — 두 번 적용해도 같고 하나 빠져도 다음에 맞춰진다.
- 좌표는 칸 정수(Q8 아님). 궤적은 2틱마다 한 점, 클라는 점 사이를 선형 보간한다.
- `shots` 가 배열인 것은 S6 의 겹씨앗·후속 홀씨탄 때문이다(MVP 는 항상 1개).
- 이동이 클라 미리보기와 다르면 클라는 `move.to` 로 고친다(서버가 이긴다).

## 7. 봇

**공개 정보만 본다**(D-118·D-119) — 이 게임은 숨긴 정보가 없어 공개 뷰 = 전체 상태다(시드 제외). 그래서 봇이 서버와 같은
시뮬레이터로 찾으면 **백발백중**이 된다. 난이도는 "찾은 정답에 사람 같은 오차를 얹는 양"으로 만든다.

### 7.1 조준 탐색

1. **표적**: 살아 있는 적 중 (체력 낮음, 가까움) 순 점수가 가장 높은 하나. 직전 차례에 쏜 표적이 살아 있으면 유지(보정 사격).
2. **거친 탐색**: 표적 쪽 반원에서 각도 5° × 힘 4 단위 ≈ 450발을 시뮬레이션. 점수 = 적 피해 합 − 1.5 × (자기 피해) − 낙사 위험.
3. **세밀 탐색**: 최고점 주변 ±4°, ±3 힘 ≈ 60발.
4. **이동**: 최고점이 기준 미만(엄폐로 막힘)일 때만 `moveDx ∈ {±15, ±30}` 4곳에서 1~3을 다시(이 경우만 시뮬이 4배).
5. **예산**: 시뮬 800발 또는 200ms 중 먼저 닿는 쪽에서 멈추고 그때까지의 최고 수.

### 7.2 난이도 = 오차

| 난이도 | 각도 오차 | 힘 오차 | 보정 사격 |
| --- | --- | --- | --- |
| 쉬움 | ±6° | ±8 | 없음 |
| 보통(MVP 기본) | ±3° | ±4 | 같은 표적 연속이면 오차 절반 |
| 어려움 | ±1° | ±1 | 오차 절반 |

- 오차는 `f(시드, 차례 번호, 좌석)` 로 정해 **같은 상태면 같은 수**(D-118 원칙 — 포트 `random` 인자는 쓰지 않는다).
- MVP 는 "보통" 하나. 난이도를 방 설정으로 고르게 할지는 §11 Q4.
- 정책이 예외·범위 밖 수를 내면 ERROR 로그 후 `timeoutAction`(SKIP)으로 폴백.
- 평가: 봇끼리 1,000판 — 보통 봇 vs 무작위 봇 승률 ≥ 90%, 쉬움 vs 보통이 보통 쪽으로 기울어야 한다(난이도 서열 확인).

### 8.2 Canvas 그리기

- 전장 640×360칸 = 16:9. MVP 는 **카메라 이동·확대 없이 전체를 한 화면**에 맞춘다(휴대폰에서 가장 단순).

- 지형: 마스크로 오프스크린 캔버스를 한 번 만들고, 구멍은 `destination-out` 원으로 지운다(매 프레임 재생성 없음).
  흙 단면·풀 윗면은 직접 만든 패턴.
- 포대·씨앗·구름은 **직접 그린 Canvas 경로/SVG**(외부 그림 금지). 하늘 그라데이션 + 구름 바다 물결 + 밀물 수면.
- 재생: `requestAnimationFrame` 으로 대본을 1/60초 기준 시간에 맞춰 진행. 탭이 숨겨졌다 돌아오면 끝 장면으로 건너뛴다.
  "움직임 줄이기"(`prefers-reduced-motion`)면 궤적을 선으로 그리고 바로 결과.
- 플레이어 줄: 전장 위/아래에 이름·계급(D-166)·체력 막대·탄 수. 채팅 한 줄(D-163)은 전장의 포대 머리 위에.
- 텍스트 기록(`aria-live`): "보라의 호박탄 — 민수 28 피해, 지수 낙하 6" — 화면을 못 보는 사람과 놓친 사람용.

### 8.3 휴대폰 터치 조작

| 조작 | 방식 |
| --- | --- |
| 이동 | 아래 [◀] [▶] 를 **누르고 있는 동안** 걷는다(미리보기). 연료 막대. 이동만으로는 서버에 아무것도 안 간다 |

| S5 | 공개 전 보강(운영 사양 벤치·문서 수치·QA 시나리오) → 공개 전환 → 배포 | S4 | 서버·클라 | `check.sh` 전체, 운영 스모크 한 판 |
| S6 | 유닛 3종 선택 + 특수탄 + 아이템 3종 | S5 | 서버·클라 | 유닛·아이템 룰 테스트, 시뮬레이션 재실행 |
| S7 | 팀전(`TEAMS`) | S5 | 서버·클라 | 팀 종료·순위·ELO 테스트 |
| S8 | (선택) 실시간 이동·조준 공유 — 포트 확장 검토 | S5 | 서버(포트)·클라 | 포트 계약 문서 선행 |

- S1 은 다른 게임 코드와 접점이 없어 바로 병행 가능하다. S4 의 Canvas 시안(정적 그림·조작부 배치)은 S2 와 병행 가능.
- 단계마다 Phase Gate(변경 요약 + 다음 진입 동의). 작업량은 원카드(S0~S5)보다 크다 — 물리 코어(S1)와 Canvas(S4)가 새 영역이다.

## 10. MVP 범위 제안 (가장 작게)

**S0~S5 = "새싹포 한 종으로 하는 개인전"**

| 넣는다 | 뺀다(후속) |
| --- | --- |
| 2~6인 개인전 | 팀전(S7) |
| 유닛 1종(새싹포) | 유닛 선택·특수탄(S6) |
| 탄 2종(콩알·호박탄 2발) | 아이템(S6) |
| 이동(연료) · 각도 · 힘 · 바람 · 지형 파괴 · 낙하 · 구름 밀물 | 지형 쌓기(덩굴탄) |
| 봇 "보통" 1단계 | 난이도 선택 |
| 한 화면 전장(카메라 없음) | 카메라 이동·확대, 큰 맵 |
| 대칭 무작위 맵 | 맵 종류 선택 |
| 이동은 발사와 한 액션 | 실시간 이동·조준 공유(S8) |

더 줄이고 싶으면 **2~4인**으로 상한을 낮춘다(6인은 한 바퀴가 길다 — 30초 × 6 + 연출 ≈ 3.5분). §11 Q1.

## 12. 결정 초안 (착수 때 `docs/decisions.md` 로 옮긴다)

- **D-?? — 네 번째 후보 게임 "씨앗포"(턴제 포격) 기획.** 하늘 정원의 화분 포대가 씨앗을 쏘는 독창 세계관으로, 기존 포격 게임의
  이름·유닛·그림·맵을 쓰지 않는다. 코드 이름은 장르명(`artillery`/`ARTILLERY`)이라 화면 이름이 바뀌어도 패키지를 안 바꾼다.
- **D-?? — 물리는 서버가 정수로 한 발에 한 번.** 고정 소수점(Q8)·삼각 정수표·자체 SplitMix64 로 결정적이고, 실시간 서버 루프는 없다.
  클라는 대본을 재생만 하고 조준 궤적 미리보기를 주지 않는다. 무료 사양에서 방당 분당 2~4발, 한 발 ≤ 6ms 로 추정(S1 실측으로 교체).
- **D-?? — 지형은 (시드, 연산 목록)으로 저장.** 비트 마스크는 파생값이라 상태가 작고, 클라에는 resync 때 RLE·이후 구멍 목록만 보낸다.
- **D-?? — 포트 변경 없이 붙인다.** 발사 뒤 연출 대기는 엔진 타이머(D-128)의 RESOLVING 단계, 비공개 뷰는 empty, 이동은 `FIRE` 에 실어
  턴 시계가 다시 걸리지 않게 한다. 실시간 이동이 필요해지면 "턴 시계 유지" 선택형 확장을 별건으로.
- **D-?? — 판 길이 상한은 구름 밀물.** 10라운드 뒤 매 차례 수면이 오르므로 판은 반드시 끝난다(불변식으로 고정).
- **D-?? — 봇은 같은 시뮬레이터로 찾고 오차로 난이도를 만든다.** 오차는 (시드·차례·좌석)에서 결정적, 예산 800발·200ms.
- **D-?? — MVP 는 새싹포 1종 개인전**(§10). 유닛·아이템·팀전·실시간 이동은 S6~S8.
