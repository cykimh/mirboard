# 티츄 봇 휴리스틱 (D-118, 트랙 A)

> 결정 근거는 `docs/decisions.md` D-118. 결정 지점별 규칙의 **정본은 `docs/rules-tichu.md` §16**
> 이고, 이 문서는 범위·실행 단위·사전 등록 기준·보정 로그·실측 수치를 남긴다.

## 범위

- **트랙 A(티츄 완성도)** 항목이다. 로드맵 M6 ③ "봇 휴리스틱"은 **스컬킹** 몫
  (`SkullKingGameEngine` 의 "D-102 보류 ②")이라 건드리지 않는다 — 스컬킹 봇은 여전히 포트 기본
  (합법 액션 균등 분포)이다.
- 티츄 봇을 "합법수 균등 무작위"(`RandomBotPolicy`)에서 공개 정보만 보는 결정적
  `HeuristicBotPolicy` 로 바꾼다. 선언·패스·리드·팔로우·폭탄·소원·개·용 양도·봉황을 모두 다루고
  파트너 선언 가드를 둔다.
- 외부 계약 변경 없음: REST/STOMP·DB 스키마·운영 설정 그대로. 포트 시그니처도 그대로이고
  티츄 `botAction` 구현만 바뀐다(`random` 인자 무시).
- 범위 밖: 엔진 갭 (a)~(d) 수정(문서화만 — `rules-tichu.md` §8.4·§9·§11), 차례 밖 폭탄
  인터럽트(BotScheduler 가 대기 좌석만 깨움 — infra 무변경), 봇 난이도 방 옵션.

## 설계 요점

| 항목 | 내용 |
| --- | --- |
| 정보 경계 | `BotView.of(state, seat)` 가 상태를 읽는 유일한 경로. 본인 손패, 좌석별 장수·선언·완주, 공개 트릭, 나온 카드(모든 tricksWon + 진행 중 트릭), 내 용 양도 보류. **안 보는 것**: 남의 손패, `reservedSecondHalf`(내 몫 포함), 남의 `Passing.submitted` |
| 결정성 | Random·시간·해시 순회 없음. 손패는 56비트 마스크(비트 번호 = 정규 카드 키 순서), 모든 선택은 총순서 min(마지막 키 = 정규 카드 순서). legal 목록 순서에 기대지 않는다 |
| 후보 | `LegalActionEnumerator.enumerateFull`(package-private) = 기존 후보 + `ComboFinder` 조합 + 선언, 같은 `ActionValidator` 로 거름. 기존 `enumerate` 와 그 9개 테스트는 그대로(포트 `legalActions`·타임아웃·랜덤 봇 후보 분포 불변) |
| 평가 함수 | `HandPlanner` — 폭탄 예약 → 4변형 그리디(스트레이트 먼저/세트 먼저 × 봉황 채우기) → (묶음 수, 루저 수) 최소. `HandDetector` 를 부르지 않는다 |
| 가드 | 제안은 `ActionValidator` 로 다시 확인, 실패 시 `TimeoutActionPolicy` 폴백(fellBack). 시뮬레이션은 fellBack 0 을 단언 |
| 배선 | `TichuGameEngine.botAction` → `HeuristicBotPolicy.choose`. 대기 좌석 계산은 `TichuPendingSeats.of` 로 옮겨 어댑터와 하네스가 공유 |

## 선언 보정 로그 (자가대전, 듀플리케이트 딜)

보정 시드와 검증 시드를 나눈다. **보정 시드** = 30000~30199(1·2차), 50000~50199·60000~60199·
70000~70199(3차에 추가). **검증 시드** = 100000~100599 — 문턱을 확정한 뒤 한 번만 돌렸고, 보정에
다시 쓰면 그 구간은 보정 시드로 옮기고 새 구간을 정한다. 아래 구간 표는 선언 순간의 손패를
(controls, 비컨트롤 묶음 = groups − controls) 로 나눈 성공률이다.

losers+1 ∧ losers ≤ 3): 티츄 **793/1276 = 0.621** → 목표 0.70 미달.

(`TICHU_MIN_CONTROLS`, `TICHU_MAX_OPEN_GROUPS`). 기존 문턱은 그대로 두었다.

## 알려진 한계 · 후속

- 랜덤·그리디 대비 우위는 "바보가 아님"의 증거일 뿐 사람 수준을 보장하지 않는다. 사람 파트너의
  매치 점수를 깎을 수 있다(봇 매치 ELO 제외 D-71, 내기 방 봇 금지 D-82 라 영향은 매치 점수 한정).
- 결정적 정책이라 소원·패스 패턴이 읽힐 수 있다 — 필요하면 시드 기반 소폭 노이즈를 후속으로.
- 엔진 갭 (a)~(d) 를 고치는 D-NN 에서 `isBoss`·F3·F4 문턱과 선언 문턱을 다시 보정한다
  (술어가 `HeuristicBotPolicy` 한 곳에 모여 있다).
- `HandPlanner` 는 나중에 ISMCTS 롤아웃 정책으로 재사용할 수 있다.
