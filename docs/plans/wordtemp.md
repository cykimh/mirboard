**왜 0건으로 되는가.** 이 게임이 새로 요구하는 것은 "잠금 밖에서 끝난 일의 결과를 나중에 상태에 넣기"뿐이다. 포트에 서버가 밀어 넣는 입구는
없지만, ⑦ 의 계약이 이미 그 일을 한다: 인프라는 발화 때 **잠금 안에서 `timer(state)` 를 다시 물어 0 이하일 때만 `onTimer` 를 부르고, 0 보다
크면 저장·방송 없이 그 시간 뒤에 다시 건다**(D-128 "락 안 재확인"). 그래서 어댑터의 `timer` 가 "채점 결과가 와 있으면 0, 아니면 250ms"를
돌려주면 결과가 올 때까지 상태를 쓰지 않고 폴링하다가, 온 순간 `onTimer` 가 반영한다. 계약의 조건("같은 상태에서 시계가 흐르면 결국 0 이하,
0 이하면 `onTimer` 가 전이를 준다")은 채점 기다림 상한 8초가 보장한다 — 8초가 지나면 결과가 없어도 0 이하이고 `onTimer` 는 그 힌트를 무효로 만든다.

- **새로운 점(위험 R2)**: 지금까지 `timer` 는 상태와 시계만의 함수였다. 여기서는 어댑터가 채점기의 결과함도 본다. 계약 문장에는 맞지만 처음
  쓰는 모양이라 S2 에서 `EngineTimerScheduler` 경로로 IT 를 붙여 고정한다(결과 도착 전 발화 → 재무장만, 도착 뒤 발화 → 반영, 상한 뒤 → 무효).
  안 되면 그때 포트 문서에 한 줄 덧붙이는 결정을 따로 쓴다(메서드 추가는 여전히 없다).
- 사라진 타이머는 진행 킥(D-130)이 다시 건다 — 게임이 할 일 없음.

## 2. 서버 구조 (2계층)

```
domain.game.wordtemp
├─ WordTempGameDefinition      @Component — 카탈로그·옵션·시간 선언, 공개 상태 설정
├─ WordTempGameEngine          포트 어댑터 — 상태 저장, 뷰, 타이머 합성, 채점 요청·결과 수거, 매치 종료 이벤트
├─ WordTempRoundStarter        GameStartingEvent 리스너 — 후보 나누기·첫 상태
├─ engine/                     순수 룰(저장소·시계·네트워크 없음)
│   ├─ WordTempEngine          apply / onDeadline / applyScore / desert
│   ├─ WordTempState·Phase·Hint·Guess (record, with*)
│   ├─ WordTempAction·WordTempEvent (sealed)
│   ├─ WordNormalizer·AnswerJudge·HintRules
│   └─ WordTempVisibility      누가 무엇을 보나(뷰·이벤트가 모두 거친다)
├─ words/
│   ├─ AnswerBank              정답 은행(낱말·범주·뜻풀이·같은 말) — 부팅 때 읽음
│   ├─ SimilarityTable         인터페이스: lookup(answer, hint) → OptionalInt, neighbors(answer)
│   └─ PackedSimilarityTable   정수 인덱스·정렬 배열 구현(§5.4) — 부팅 때 읽음
├─ scoring/
│   ├─ LiveHintScorer          인터페이스: request(pair) / poll(pair) → 결과｜없음
│   ├─ ClaudeHintScorer        공식 Anthropic Java SDK, 가상 스레드, 상한·끄기
│   └─ LiveScoreStore          Postgres 캐시(word_temp_live_scores)
├─ bot/WordTempBotPolicy       출제·추리 정책(BOT_LEVEL)
└─ persistence/                매치 기록기·엔티티·HeadToHeadSource
```

- *S2 구현(D-316~D-318)*: 위 그림과 달라진 것 — 순수 계층은 아래 줄대로, `words/` 에 `WordTempWords`(자원 Bean)·`PackedSimilarityTable`, `scoring/` 은
  `LiveHintScorer` ← `AsyncLiveHintScorer`(가상 스레드·상한·결과함) + `HintJudge` ← `ClaudeHintJudge`(SDK 호출 한 번) + `LiveScoreStore` ← `JdbcLiveScoreStore`,
  스타터는 `lifecycle/`. **설정 이름**은 §5.5 의 `mirboard.wordtemp.live.*` 가 아니라 `mirboard.wordtemp.model` + `mirboard.wordtemp.live-scoring.*`(D-317),
  기다림 상한 8초는 설정이 아니라 `WordTempTuning.liveWaitMs`. 시작 이벤트는 방송하지 않는다(§3.1 의 "스타터가 낸다"를 바꿈 — resync 로).
  저장된 실시간 점수의 "메모리 캐시 조회"(§4.2 ①)는 두지 않았다 — 이미 매긴 쌍도 채점 중으로 들어가 작업이 Postgres 를 읽고 다음 폴링(≤250ms)에 반영된다.
  봇 강도 표(`MIRBOARD_BOT_EVAL`)와 Fly 리전 지연 측정은 하지 않았다(S4 전). 실제 키 확인은 한 판이 아니라 호출 6번(스모크 테스트)이다 — 클라가 없어 판을 돌릴 수 없다.
- *S1b 구현(D-315)*: 순수 계층은 `engine/` 한 묶음이 아니라 별자리 수판·담바둑처럼 `WordTempEngine`(루트) + `rules`·`state`·`action`·`event`·`bot`·`invariant`·`words` 로 나눴다(위치 표는 룰 §18). 채점 결과 반영은 `applyScore`, 단계 마감은 `onTimer`/`TICK`.
- 순수 엔진은 `SimilarityTable`·시각·난수 씨앗을 **인자로** 받는다. 테스트는 작은 고정 표를 쓴다(Redis·DB·네트워크 없음).
- 채점기·SDK 는 게임 패키지 안에 둔다 — 인프라에 게임 이름을 넣지 않으려는 것이다(`grep -rni "wordtemp\|word_temp" server/src/main/java/com/mirboard/infra` 0건이 완료 조건).
- 의존성: `server/build.gradle.kts` 에 `com.anthropic:anthropic-java`(버전은 S2 착수 때 최신 안정판으로 고정). 저장소의 첫 외부 API 클라이언트다.

## 3. 상태 스케치

```
WordTempState
  config        { rounds, hintSeconds, botLevel, tableVersion, seed }
  seats[]       { userId, bot, alive, score{setter, guess}, candidates[], used[], chosen(이번 라운드) }
  order[]       출제 순서(좌석 번호)
  round, turnNo, setterSeat, attempt
  phase, phaseStartedAt, hintClosed(마감 뒤 채점만 기다리는 중)
  answer        이번 출제 차례의 정답 낱말(문자열 — 표 인덱스가 아니라 낱말 자체: 표 버전이 바뀌어도 읽힌다)
  hints[]       { text, attempt, status: SCORED｜PENDING｜VOID, temp?, source: TABLE｜LIVE, requestedAt? }
  revealed[]    차수별 공개 힌트 { attempt, text, temp, floorMet }
  guesses{}     이번 차수 좌석 → { text｜PASS, at }
  botPlan[]     { seat, at, kind } 봇이 행동할 시각(씨앗에서 결정)
  history[]     끝난 출제 차례 요약(결과 화면·기록용 — 정답·공개 힌트·맞힌 좌석)
  endReason?
```

- JSON 으로 영속되는 record 라 필드를 더할 때는 compact constructor 에서 null 정규화(CLAUDE.md 규칙).
- **확정 온도는 `hints[].temp` 에 들어간다** — resync·`TURN_ENDED`·기록은 여기서 읽고 표·채점기를 다시 부르지 않는다.
- 크기: 6인·3라운드 최악에도 수십 KB 미만(힌트 최대 18차례 × 15개).

### 3.1 이벤트 — 공개(순번 있음) / 비공개(순번 없음)

목록은 룰 §12.2·§12.3. 원칙만:

- 공개 상태가 바뀌면 **반드시 공개 이벤트**(개수 `HINT_COUNT`, 제출 표시 `GUESS_SUBMITTED`, 공개 `HINT_REVEALED`·`GUESSES_REVEALED`·`TURN_ENDED`).
- 비공개 이벤트(`WORD_CANDIDATES`·`HINT_SCORED`·`HINT_PENDING`·`HINT_VOID`·`GUESS_ACCEPTED`)는 `sequenced() = false`(D-126).
- 시작 때 `MATCH_STARTED` 를 방송하지 않는다 — 시작 상태는 resync 로(원카드와 같다). 첫 `WORD_SELECT_STARTED` 는 스타터가 낸다.
- 공개 이벤트·공개 뷰 타입에는 `answer`·미공개 힌트·미공개 추리 필드가 **없다**. `TURN_ENDED` 만 정답을 싣는다.

## 4. 비동기 채점 경로 (D-312)

### 4.1 왜 잠금 밖인가

`RoomActionLock` 은 TTL 2초이고 액션 경로는 기다리지 않고 `BUSY` 로 거절한다. 실측한 Claude 호출은 p50 약 2초·p90 약 3초(§5.5)라 `apply`
안에서 부르면 잠금이 풀린 채 상태를 덮거나 같은 방의 다른 진행이 막힌다.

### 4.2 한 걸음씩

```
① SUBMIT_HINT 도착 ─ 잠금 안 apply
     형식·포함·중복·개수 검사(룰 §5.2)
     표 조회 ── 있음 → hints += SCORED(temp)         → 비공개 HINT_SCORED, 공개 HINT_COUNT        (끝)
            └─ 없음 → 저장된 실시간 점수 메모리 캐시 조회 ── 있음 → 위와 같음(source LIVE)
                    └─ 없음 → 실시간 채점 가능? (켜짐·하루 상한·판 상한)
                               ├─ 아니오 → ERROR UNKNOWN_WORD (개수 유지)
                               └─ 예 → hints += PENDING(requestedAt = now)
                                       어댑터가 scorer.request(answer, hint) — 가상 스레드에 맡기고 바로 반환
                                       → 비공개 HINT_PENDING, 공개 HINT_COUNT
② 잠금 밖 ─ ClaudeHintScorer (방·사용자를 모른다 — (정답, 힌트) 쌍만 안다)
     Postgres 캐시 읽기(이미 있으면 그 값) → 없으면 Claude 호출(§5.5) → 결과를 캐시에 INSERT … ON CONFLICT DO NOTHING
     → 다시 읽은 값(먼저 쓴 쪽이 이김)을 결과함(메모리, 쌍 → 결과)에 넣는다. 실패·시간 초과·거절은 "실패"로 넣는다.
③ 엔진 타이머 ─ 어댑터 timer(state)
     PENDING 이 있으면: 결과함에 결과가 있거나 requestedAt + 8초가 지났으면 0, 아니면 250ms
     (단계 마감·봇 시각과 min — 단, PENDING 동안 단계 마감은 미룬다)
     인프라: 0 보다 크면 저장·방송 없이 그 시간 뒤 다시 건다 / 0 이하면 onTimer
④ onTimer ─ 잠금 안
     결과 있음·명사 → SCORED(temp)   → 비공개 HINT_SCORED   (96 이상이면 힌트 단계 종료 → 공개 HINT_REVEALED …)
     결과 있음·명사 아님 → VOID       → 비공개 HINT_VOID{NOT_A_NOUN}, 공개 HINT_COUNT(개수 −1)
     결과 없음(8초)·실패 → VOID       → 비공개 HINT_VOID{SCORING_FAILED}, 공개 HINT_COUNT
     hintClosed 였다면 이어서 단계 종료 전이
```

### 4.3 타이머 합성

`timer(state)` = 다음 중 가장 이른 것까지 남은 시간:

1. 단계 마감(`phaseStartedAt + 길이`) — `HINT` 에서 PENDING 이 있으면 제외(대신 2 가 상한 8초로 끝을 보장).
2. 채점 폴링(위 ③).
3. 다음 봇 행동(`botPlan` 의 가장 이른 `at`).

`onTimer` 는 만기된 것을 정해진 순서(채점 반영 → 봇 행동 → 단계 마감)로 **하나만** 처리하고, 남은 것은 다음 발화가 처리한다(전이 하나 = 방송 한 묶음).

### 4.4 가장자리

| 상황 | 동작 |
| --- | --- |
| 서버 재시작(작업·결과함 유실), 상태에는 PENDING | `poll` 이 결과함에 없고 진행 중 작업도 없으면 작업을 **다시 건다**(작업은 먼저 Postgres 를 읽으므로 이미 채점됐으면 호출 없음). 8초 상한은 `requestedAt` 기준 그대로 |
| 인스턴스 여럿(지금 운영은 1대) | 타이머가 다른 인스턴스에서 발화하면 위와 같은 길 — 결과는 Postgres 로 모인다. 폴링 중 DB 읽기는 쌍마다 초당 1회로 제한 |
| `apply` 뒤 상태 저장 실패 | 요청만 나간 것 — 결과는 캐시에 남아 다음에 쓰인다 |
| 같은 쌍을 두 방이 동시에 | 작업은 쌍마다 하나로 합친다(진행 중 맵). DB 는 먼저 쓴 값이 정본 |
| 채점 중 출제자 탈주·강퇴 | 차례를 끝내며 PENDING 을 버린다. 뒤늦은 결과는 캐시에만 남는다 |
| 채점 중 힌트 제한 만료 | `hintClosed = true`, 결과(또는 8초) 뒤 단계 종료. 새 힌트·[힌트 끝] 거절 |
| 끄기 스위치·상한·API 키 없음 | ① 에서 `UNKNOWN_WORD`. 게임은 표만으로 진행 |
| Claude 가 거절(`stop_reason: refusal`)·형식 밖 응답 | 실패로 처리(무효·개수 반환). 캐시에 쓰지 않는다 |
| 점수가 0~100 밖 | 0~100 으로 자른다(스키마가 범위를 강제하지 못할 때의 방어) |

### 4.5 "들어오는 길" 전부에 대한 확인 (S2 테스트 목록)

클라 액션 · 턴 타임아웃(`TICK`) · 엔진 타이머 · 탈주 · 방장 강퇴(`HostKickService`) · 강제 종료(`GameAbortService`) · resync —

### 5.4 파일 형식과 메모리

- 파일: gzip 한 줄 단위 텍스트 — `정답 \t 힌트:온도,힌트:온도,…`, 첫 줄에 `version`·`promptVersion`·`model`·만든 날. 사람이 diff 로 읽을 수 있고 수백 KB 다.
- **부팅 때** 읽는다(`@Component` 생성 시 — 별자리 수판 `PuzzleBank` 와 같은 때). 첫 판·`apply` 에서 파싱하지 않는다.
- 메모리 꼴(비평가 정정 반영): 힌트 어휘는 정렬된 `String[]`(이진 탐색으로 인덱스), 정답마다 **정렬된 `int[]` 힌트 인덱스 + `byte[]` 온도**.
  `Map<String, Map<String,Integer>>` 로 담지 않는다.
- 어림: 10만 쌍 × 5바이트 ≈ 0.5MB + 어휘 2~3만 낱말 문자열 ≈ 2MB → **힙 5MB 이하** 목표(최대 힙 약 280MB). S2 완료 조건에 운영 힙 실측(표를 싣기 전후).
- 형태 검증 테스트: 모든 정답이 은행에 있음, 온도 0~100, 힌트가 룰 §5 를 통과, 인덱스 정렬, 은행 기준(§5.1) 충족.
- 표 밖 = "모름"이지 "낮은 점수"가 아니다 — 표에 없는 쌍에 고정 저점을 주지 않는다(실시간으로 묻거나 거절).

| `word_temp_live_scores` | `answer`, `hint`, `model`, `prompt_version`(이 넷이 PK), `valid`, `score`, `hits`, `created_at`, `last_seen_at` | 실시간 점수 캐시 **겸 놓친 낱말 수집**. `users` FK 없음 |

- **놓친 낱말 수집: 한다** — 따로 표를 만들지 않고 `word_temp_live_scores.hits`(같은 쌍이 다시 나올 때 +1)로 겸한다. 사용자·방 식별자·시각별 기록 없음,
  낱말은 형식 검사를 통과한 한글 1~10자뿐. 실시간 채점이 꺼져 거절된 낱말은 모으지 않는다(v1). 보는 것은 운영자의 SQL 뿐(어드민 화면 없음).
- 사용자가 친 **오답 원문은 어디에도 저장하지 않는다**. 힌트 낱말은 위 캐시와 payload(공개된 것)에만 남는다 — 개인정보 최소화 원칙과 부딪히지 않는다(낱말일 뿐 식별 정보 아님).
- `users` 컬럼은 건드리지 않는다. 운영 DB 는 Supabase `mirboard` 스키마(D-169) — 테이블은 지금처럼 Flyway 가 만든다.
- 번호는 파일 이름에만 둔다(병렬 작업이 먼저 V25 를 쓰면 관제가 순서대로 고친다).

## 7. 클라 설계 (S3 — 디자인·연출·소리는 Fable 5.2)

- `features/wordtemp/`: `wordTempStore`(순수 리듀서, `lastSeq` 없음) · `wordTempSink`(모듈 상수 `RoomEventSink`, 메서드마다 `getState()`) ·
  `WordTempTable`(자기 소켓 소유) · `tutorial/`(`gameTutorials.ts` 에 한 줄) · 게임판은 `pages/gameTables` 지연 로딩(정적 import 금지).
- 화면(휴대폰 375×812 우선): 위 좌석 띠(`tableLayout`, 출제자 표시·점수·"냈음" 표시) → 가운데 **온도계 판**(공개 힌트가 온도 순으로 쌓임, 띠 색) →
  아래 내 칸(출제자: 힌트 입력·내 힌트와 온도·"힌트 3/5"·[힌트 끝] / 추리자: 답 입력·[패스]) — 키보드가 올라와도 공개 힌트와 남은 시간이 보이게.
- 테마 "온도계": 차가움(푸른빛) → 미지근 → 뜨거움 → 96 이상 "끓음". 공개 순간 수은주가 차오르는 연출, 정답 순간 강조. 그림은 인라인 SVG·CSS 만.
- **채점 중**: `HINT_PENDING` 을 받으면 그 힌트 줄에 "채점 중…"과 입력 잠금, `HINT_SCORED`/`HINT_VOID` 로 푼다(무효는 토스트가 아니라 `ErrorNotice` 계열 안내 —
  "명사가 아니에요. 개수는 돌려드렸어요" / "채점이 늦어졌어요. 다시 내 주세요").
- **한글 입력**: `compositionend` 전의 Enter 는 보내지 않는다(조합 중 반쪽 글자 방지), 보내기 전 클라도 NFC·공백 제거(서버가 정본). 입력란은 게임판 글자 선택 막기(D-292)의
  예외. 자동 완성·맞춤법 제안 끔.
- 보내기: `SUBMIT_HINT`·`SUBMIT_GUESS` 의 `BUSY` 는 한 번 재전송(요트와 같다), 버튼은 응답 전 `aria-disabled`.
- 남은 시간은 공개 뷰 `phaseRemainingMs` + 단계 시작 이벤트로 그린다(바깥 `turnRemainingMs` 쓰지 않음).
- CSS: `29-wordtemp-table.css`, 접두 `.wt-`, 공용 클래스 재정의 금지, 스코프에서 `box-sizing` 명시, 반응형은 `17-responsive.css` 의 `.wt-` 블록,
  동작 줄이기는 `:root:not(.motion-forced)` + `:root.motion-off` 짝(D-291), 글꼴 지정 없음.
- 소리: `tableSfx` 톤(D-271) — 힌트 제출·온도 공개(온도 높이에 따라 음 높이)·정답·차례 끝. 음성 클립은 v1 에 없음.
- 튜토리얼(자동 노출 없음, D-154): 5~6장 — 목표 / 출제자 화면 / 최저 온도 / 추리 / 점수 / **"채팅으로 정답을 알려 주면 재미가 없어요"**.
- 결과 화면: 순위·출제 점수·추리 점수, 출제 차례별 정답과 공개 힌트. 대기실 복귀(D-153)·`roomFinished` 처리는 다른 게임과 같다.
- 관전자: 공개 뷰만 — 출제자 칸·추리 칸 없이 판만 본다.

**S3 결과(D-319)** — 위 설계대로 붙였다. 달라진 것·덧붙인 것만:
- 테마 이름 "겨울 창가의 유리 온도계". 온도계는 **눕힌 한 줄**(구 → 관 → 숫자)이라 공개 힌트 셋이 쌓여도 휴대폰 한 화면에 든다. 좌석은 `tableLayout`
  (가운데 판을 둘러앉기)이 아니라 위 **좌석 띠**(4인 2×2, 5~6인 3열) — 가운데에 둘 판이 글자 목록이라 세로 공간을 입력에 준다.
- 입력란은 공개 힌트 판 바로 아래, 머리 줄(시계)은 붙박이 — 자판이 올라온 높이(375×480)에서도 공개 힌트·시계·입력란이 같이 보인다(스크린샷 `05b`·`07b`).
- 넓은 화면(900px~)은 왼쪽 온도계 판·오른쪽 내 칸 두 단.
- 소리는 `temp.send`·`temp.scored`·`temp.reveal`·`temp.boil`·`temp.correct`·`temp.wrong`·`temp.answer`(차례 끝의 정답 공개).
- 화면이 쓰는 값은 서버가 싣는다(D-319 덧붙임): 공개 뷰 `floors`(차수별 최저 온도), 후보의 범주 이름·뜻풀이, 결과 보기·차례 끝의 남은 시간, 판 시작 때 저장 뒤 `WORD_SELECT_STARTED`. 클라의 표시용 상수·범주 표는 걷었다.
- e2e: `client/e2e/wordtemp.e2e.ts`(봇 둘과 짧은 판 끝까지, `E2E_WORD_TEMP=1`), 스크린샷 도구 `client/e2e/wordtempShots.mjs` → `client/e2e/wordtemp-shots/`.

## 11. 룰 v2 (D-320, 2026-11-27)

정본은 `docs/rules-wordtemp.md` §3.2·§3.4·§11·§12·§15.1. 여기에는 바뀐 곳과 수치만.
