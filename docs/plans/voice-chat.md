# 음성 대화 — 무료 P2P(WebRTC) (D-155, 승인 2026-10-30)

## 왜·무엇

원카드를 하면서 친구끼리 말로 대화하고 싶다(사용자 요청 2026-10-30). 운영은 무료 범위만 쓴다. 그래서 소리는 서버를 거치지 않고
**브라우저끼리 직접(P2P, WebRTC)** 보내고, 서버는 연결을 맺기 위한 짧은 메시지만 중계한다.

## 사용자 결정 (2026-10-30)

- 무료 P2P만 쓴다. 공개 STUN(구글)만 쓰고 중계(TURN)는 두지 않는다.
  - 그래서 일부 휴대폰 통신망이나 회사망에서는 연결이 안 될 수 있다.
  - 그 사람과는 "연결 안 됨"만 보인다.
- 마이크는 켜기/끄기 토글이다. 처음에는 꺼져 있다. 다른 사람 소리 듣기도 따로 켜고 끈다.

## 동작

1. **🎧 음성 참여(듣기)** — 누르면 이 방의 음성 대화에 들어간다.
   - 이미 참여한 사람들과 하나씩 연결한다(메시 — 6명이면 각자 5개 연결).
   - 이때는 마이크 권한을 묻지 않는다.
   - 다시 누르면 나간다.
2. **🎙 마이크** — 참여 중에 누르면 그때 처음 마이크 권한을 묻고 내 소리를 보낸다. 다시 누르면 음소거된다.
   - 연결을 다시 맺지 않고 송신 트랙만 바꾼다(`sendrecv` 트랜시버 + `replaceTrack`).
3. **표시**
   - 좌석 이름 옆: 음성 참여 중이면 🎧, 나와 연결이 실패한 상대는 흐린 🎧✕("음성 연결 안 됨").
   - 말하는 중 표시(소리 크기 감지)는 이번에 넣지 않았다 — 후속 후보.
4. **대상** — 그 방의 플레이어와 관전자. 봇은 없다. 방을 나가거나 게임판을 떠나면 자동으로 나간다.

## 서버 (중계만, 저장 없음)

- 클라 → 서버 `/app/room/{roomId}/voice` 로 `{ type, to?, data? }` 를 보낸다.
  - `type` 은 `JOIN`·`LEAVE`·`OFFER`·`ANSWER`·`ICE` 중 하나다.
- **방 안 공지** — `JOIN`·`LEAVE` 는 `/topic/room/{roomId}/voice` 로 `{ type, userId }` 를 공지한다. 새로 들어온 사람이 기존
  참여자에게 OFFER 를 보낸다.
- **일대일 중계** — `OFFER`·`ANSWER`·`ICE` 는 `to` 사용자에게만 보낸다.
  - 경로: `StompPublisher.publishToUser` → `/user/queue/room/{roomId}/voice`
  - 싣는 것: `{ type, from, data }`
- **검증**
  - 보낸 사람과 받는 사람이 둘 다 그 방의 플레이어나 관전자여야 한다.
  - `data` 는 해석하지 않고 그대로 넘긴다. 길이 상한은 16KB 다.
  - 레이트리밋은 새 버킷 `voice` 로 둔다.
- 서버는 누가 참여 중인지 기억하지 않는다.
  - 새로 들어온 사람은 `JOIN` 을 공지한다.
  - 이미 참여 중인 사람들은 그 공지를 받으면 자기 `JOIN` 을 다시 공지한다(한 번).
  - 그러면 서로 알게 된다. 상태 키가 없으니 멀티 인스턴스에서도 같다.
- **누가 OFFER 를 보낼지** — 두 사람 중 userId 가 작은 쪽이 보낸다(양쪽이 동시에 보내는 충돌 방지).

## 클라

- `ws/useVoiceChat.ts`
  - 방 소켓(`useStompRoom`)에 음성 구독·발신을 더한다.
  - 상대별로 `RTCPeerConnection` 을 둔다.
  - STUN 은 `stun:stun.l.google.com:19302` 다.
  - 받은 소리는 숨긴 `<audio autoplay>` 로 재생한다.
  - 게임 중립이다. 먼저 원카드 머리 줄에 🎧·🎙 를 단다. 티츄·스컬킹도 같은 훅을 쓰면 된다.
- 테스트
  - jsdom 에는 WebRTC 가 없다. 그래서 신호 흐름(누가 OFFER 를 보내는지, 나가면 정리되는지)을 가짜 `RTCPeerConnection` 으로
    단위 테스트한다.
  - 실제 소리는 휴대폰 두 대로 사람이 확인한다(qa-scenarios).

## 한계·위험

- 중계 서버가 없어 대칭 NAT(일부 LTE·회사망) 사이에서는 연결되지 않는다. 무료 유지의 대가로, 실패한 상대만 "연결 안 됨"으로 보인다.
- 메시라 인원이 많으면 휴대폰 데이터와 배터리를 많이 쓴다. 원카드 최대 6명이면 5개 연결이다.
- 브라우저 자동 재생 정책 때문에 🎧 을 누르는 동작(사용자 제스처)으로 재생을 시작한다.
- 녹음·저장은 하지 않는다. 서버는 소리를 보지 못한다(P2P, DTLS-SRTP 암호화).
