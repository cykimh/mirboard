# 방 만들기 두 갈래 — 친구와 하기 / 봇과 연습, 지금 인원으로 시작 (D-136) — 설계

> 상태: **구현** · 2026-10-14(설계 승인 → 구현) · 결정 이력 `docs/decisions.md` D-136
> 근거: 사용자 방향("사람들이랑 게임할 때는 봇을 다 없앨 거야. 방 만들 때도 앞으로 봇 없앨 예정이야", 2026-10-12) · 봇 채우기(Phase 9B·D-117)
> · 방 초대 링크(D-133) · 방장 강제 종료 봇 판만(D-135)

## 1. 목표와 성공 기준

사람과 하는 판에는 봇이 섞이지 않는다. 봇과 하는 판은 "혼자 연습"으로 따로 두어 대기실 없이 바로 시작한다. 친구가 정원만큼 모이지 않아도
방장이 지금 모인 인원으로 시작할 수 있다.

| # | 기준 | 확인 방법 |
| --- | --- | --- |
| 1 | 방 만들기 맨 위에서 "친구와 하기 / 봇과 연습"을 고른다. 처음 선택은 누구나(게스트 포함) "친구와 하기" | 모달 테스트 |
| 2 | 친구와 하기 방에는 봇이 들어가지 않는다(봇 옵션 없음). 대기실·초대 링크·준비 흐름은 지금 그대로 | 모달·서버 테스트 |
| 3 | 봇과 연습을 누르면 방장 + 봇으로 방이 만들어지고 **곧바로 게임판**이 뜬다(대기실 없음) | 서버 IT(만들기 응답이 IN_GAME)·모달 테스트 |
| 4 | 봇과 연습 방은 대기 중인 방 목록에 한 번도 오르지 않는다(초대 버튼도 없다 — 대기실이 없으므로) | 서버 IT(`rooms:open` 에 없음) |
| 5 | 친구와 하기 대기실에서 사람이 게임 최소 인원 이상이고 방장 말고 모두 준비했으면 방장에게 "지금 N명으로 시작"이 보이고, 누르면 정원이 N 으로 줄며 시작한다 | 서버 단위·IT, 대기실 테스트 |
| 6 | 티츄(4인 고정)에는 "지금 N명으로 시작"이 없다 | 대기실 테스트 |
| 7 | 기존 흐름 회귀 0 — 정원이 다 차고 전원 준비하면 자동 시작, 초대·관전·재접속·강제 종료(봇 판) | 클라·서버 전체 |

## 2. 확정 결정 (사용자, 2026-10-14)

| 항목 | 결정 |
| --- | --- |
| 봇 판 | **"혼자 연습"으로 따로** — 사람은 나 혼자, 대기실 없이 바로 시작, 방 목록 없음, 초대 없음 |
| 인원 부족 | **방장이 "지금 인원으로 시작"** — 게임 최소 인원 이상 + 전원 준비면 정원을 현재 인원으로 줄여 시작(티츄 해당 없음) |
| 게스트 처음 선택 | **친구와 하기** |
| 연습 첫 튜토리얼 | **띄우지 않는다** — 연습은 대기실이 없어 D-121 자동 노출이 없다. 게임판 "규칙"·허브 "게임 방법"으로 본다 |
| 연습 방 관전 | **막지 않는다** — 목록·초대가 없어 방 ID 를 알 일이 드물고, 관전은 해가 없다(서버 변경도 준다) |

기각: 지금 체크박스를 두고 기본만 끄기(사람 판에 봇이 섞일 수 있음 — 방향과 다름), 정원이 찰 때까지 기다리기만(친구 3명이 모였는데 4인 방을 다시
만들어야 함).

## 3. 지금 구조 (조사, 2026-10-14)

- **봇이 들어가는 길은 하나**: `RoomService.createRoom` 의 `fillWithBots` 블록이 정원 − 1 만큼 봇을 `joinRoom` 하고 봇 좌석마다 `setReady(true)`.
  리매치·탈주·스케줄러는 봇을 더하지 않는다. `fillWithBots` 는 방 해시에 저장되고 `botSeats` 는 조회 때 파생.
- **시작**: `room_ready.lua` — `#players >= capacity` 그리고 `SCARD(ready) >= capacity` 면 `status=IN_GAME` + `ZREM rooms:open`, 자바 `onGameStart` 가
  좌석 섞기(RANDOM) 뒤 `GameStartingEvent`. 최소 인원 개념이 없다. 사람 방장도 `setReady(host, true)` 한 번이면 같은 길로 시작한다(봇만 있는 방은
  이미 `createRoom` 안에서 시작된다 — `BotMatchSimulationIT`).
- **정원(capacity)**: `room_create.lua` 만 쓴다(불변). 읽는 곳 — `room_join.lua`·`room_ready.lua`, `joinOrReconnect`, `RoomController.occupiedSeat`
  (`playerIds.size() != capacity` 면 관전자 취급 — **정원을 줄여 시작하면 반드시 함께 줄인다**), 허브·대기실 표시, 초대 `full`, 미리보기.
  라운드 시작기는 `GameStartingEvent.playerIds().size()` 를 본다 — 원카드 2~6, 스컬킹 2~8, 티츄 정확히 4.
- **방 목록**: `rooms:open` ZSET — `room_create.lua` 가 **무조건** ZADD, IN_GAME 전이·종료·소멸에서 ZREM. 허브는 5초 폴링, "🤖 솔로" 배지.
- **방 만들기 모달**: 게임·이름·인원(가변 게임만)·목표 점수·턴 제한·판돈(티츄)·"🤖 빈 좌석 봇으로 채우기". 게스트는 봇 체크가 켜진 채 열림
  (`GameHubPage` `defaultFillWithBots={!!user?.guest}`). 만든 뒤 `/rooms/:id` 로 이동.
- **봇 관련 규칙**: 판돈 방 봇 금지(`STAKED_ROOM_NO_BOTS`), 봇이 낀 매치 ELO·칩 정산 제외, 봇 판만 방장 강제 종료(D-135), 봇 낀 판 리매치 없음.

## 4. 설계

### 4.1 API — `fillWithBots` 가 곧 "봇과 연습"

- 요청 필드는 그대로 `fillWithBots`(하위 호환). 뜻이 "빈자리를 봇으로"에서 **"봇과 연습 방"**으로 바뀐다 — `true` 면:
  1. 방을 만들 때 `rooms:open` 에 **넣지 않는다**(`room_create.lua` 에 ARGV 플래그 — 목록에 한 순간도 오르지 않게).
  2. 봇으로 정원을 채우고(지금 그대로) 봇 준비(지금 그대로) 뒤 **방장 준비까지** 넣어 기존 `room_ready.lua` → `onGameStart` 로 시작한다. 응답 방은 IN_GAME.
- `false`(친구와 하기)는 지금 그대로 — 봇이 들어갈 길이 없다(봇 추가 경로는 `createRoom` 하나뿐).
- 판돈 방 + 봇 금지는 그대로(판돈은 친구와 하기에서만).
- 응답·이벤트: 방이 IN_GAME 으로 생기므로 `RoomChangedEvent` 는 시작 뒤 방을 실어도 된다(목록 구독자는 IN_GAME 을 거른다).

### 4.2 지금 인원으로 시작 — `POST /api/rooms/{roomId}/start` (방장)

- 조건: 방장, WAITING, `#players >= def.minPlayers()`, `#players < capacity`(정원이 다 찼으면 지금처럼 준비로 자동 시작), 방장 말고 **모두 준비**.
  방장이 누르는 것을 방장의 준비로 친다.
- 새 Lua `room_start_now.lua` 한 번에: 방 없음 −1, WAITING 아님 −2, 멤버 아님 −3, 인원 미달 −4, 준비 안 된 사람 있음 −5 → 아니면 방장 SADD ready,
  `HSET capacity=#players status=IN_GAME`, `ZREM rooms:open`, 1. 자바는 1 이면 `RoomChangedEvent` + `onGameStart`(기존 시작과 같은 길 — 좌석 섞기·
  `GameStartingEvent`). join 과 같은 키를 원자적으로 다루므로 "확인과 시작 사이에 누가 들어옴"이 없다(들어오면 −5 또는 정원 계산이 그 사람을 포함).
- 오류: `NOT_HOST`(403), `GAME_ALREADY_STARTED`(409 — −2), `NOT_ENOUGH_PLAYERS`(409 — −4, `minPlayers` 동봉), `PLAYERS_NOT_READY`(409 — −5),
  `ROOM_NOT_FOUND`(404). 정원이 이미 다 찼으면(`#players == capacity`) −6 → `ROOM_ALREADY_FULL`(409 — 준비로 시작하라는 뜻).
- 정원을 줄이므로 시작 뒤 `occupiedSeat`·미리보기·허브 표시가 그대로 맞는다. 줄인 정원은 되돌리지 않는다(FINISHED 방 좌석 고정 D-122).

### 4.3 클라 — 방 만들기 모달

- 맨 위 두 갈래 토글(`role="radiogroup"` "방 종류"): **친구와 하기**(기본) / **봇과 연습**.
  - 친구와 하기: 지금 폼에서 봇 체크박스만 뺀다(이름·인원·목표 점수·턴 제한·판돈).
  - 봇과 연습: 게임·인원(가변 게임만 — "봇 N명" 설명)·턴 제한. 이름 입력은 없고 "{게임 표시 이름} 연습"으로 보낸다. 판돈·목표 점수 없음(목표 점수는 티츄
    기본값). 버튼 문구 "연습 시작".
- `GameHubPage` 의 `defaultFillWithBots={!!user?.guest}` 를 지운다(게스트도 친구와 하기).
- 만든 뒤 지금처럼 `/rooms/:id` 로 이동 — 연습 방은 IN_GAME 이라 `RoomPage` 가 곧바로 게임판을 그린다(D-121 자동 튜토리얼은 대기실에서만이라 뜨지 않는다 —
  결정대로).

### 4.4 클라 — 대기실 "지금 N명으로 시작"

- `RoomPage` 대기실 준비 줄 옆: 방장이고 `room.playerCount >= minPlayers`(카탈로그 `GameSummary.minPlayers`), `playerCount < capacity`, 방장 말고 모두 준비
  (`readyUserIds`)일 때 "지금 N명으로 시작" 버튼. 티츄는 `minPlayers == capacity` 라 조건이 성립하지 않는다.
- 조건이 안 되면 숨긴다(설명 줄: 방장에게만 "2명 이상 모이고 모두 준비하면 지금 인원으로 시작할 수 있어요" — 가변 게임만).
- 누르면 `roomsApi.startNow` → 메타로 IN_GAME 이 오면 게임판(지금 흐름). 오류는 서버 문구가 아니라 한국어로(`PLAYERS_NOT_READY` "아직 준비하지 않은 사람이
  있어요", `NOT_ENOUGH_PLAYERS` "2명 이상 모여야 해요" 등).
- 대기실 안내 "(봇은 자동 준비)"는 지운다(친구와 하기 방에 봇이 없다).

### 4.5 문구·표시 정리

- 허브 방 목록의 "🤖 솔로" 배지 — 연습 방이 목록에 없으므로 지운다.
- 티츄 게임판 머리 줄 "🤖 솔로 모드 (봇 N명)" → "🤖 혼자 연습 (봇 N명)". 원카드·스컬킹은 머리 줄에 연습 표시를 하나 둔다(같은 문구).
- 스컬킹 튜토리얼 "방을 만들 때 '빈 좌석 봇으로 채우기'를 켜면…" → "방 만들기에서 '봇과 연습'을 고르면…". 다른 게임 튜토리얼도 같은 표현을 찾는다.
- 문서: `docs/api.md`(방 만들기 `fillWithBots` 뜻, 새 `/start`), `docs/redis-keys.md`(`rooms:open` 에 연습 방 없음, capacity 는 "지금 시작"에서 한 번 줄 수 있음),
  `docs/qa-scenarios.md`, `CLAUDE.md` 사용자 플로우(봇 자동 채움 줄), `docs/implementation-status.md`.

## 6. 테스트

- 서버 단위(Docker 불필요): `RoomService.startNow` 갈래 — 방장 아님, 최소 인원 미달, 준비 안 됨, 성공 시 `onGameStart` 와 `RoomChangedEvent`(저장소 모의).
  연습 만들기 시 방장 준비 호출.
- 서버 IT(Docker): 연습 방 만들기 → 응답 IN_GAME·`rooms:open` 에 없음·`GameStartingEvent` 로 라운드 시작(원카드·스컬킹·티츄), `/start` 성공(3/4 원카드 →
  capacity 3, IN_GAME, 비공개 손패가 세 좌석 모두에 — `occupiedSeat`), `/start` 거절 갈래(−4·−5·−6·NOT_HOST), 기존 `RoomControllerIntegrationTest` 솔로 테스트
  (WAITING 기대)는 새 뜻(IN_GAME)으로 고친다. `BotMatchSimulationIT` 등 봇 IT 는 영향 확인.
- 클라: 모달(두 갈래 토글, 기본 친구와 하기, 게스트도, 연습은 이름·판돈 없음·요청 `fillWithBots: true`), 허브(게스트 기본값 삭제, 솔로 배지 없음),
  대기실(지금 시작 버튼 조건 — 방장·최소 인원·모두 준비·정원 미만·티츄 없음, 오류 한국어), 게임판 연습 표시.

## 7. 후속

- 연습 방 전용 봇 난이도 선택(지금은 게임별 결정적 정책 하나).
- 친구와 하기 대기실에서 방장이 정원을 늘리기(지금은 줄이는 것만 — 시작할 때).
