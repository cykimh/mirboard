# 다음 판 — 같은 방 대기실로 돌아가고 관전자는 자동으로 앉는다 (D-153, 승인 2026-10-30)

## 왜

2명이 원카드를 하다가 초대 링크로 세 번째 친구가 들어오면 지금은 **관전**으로만 들어온다(D-133). 그런데 원카드·스컬킹은 판이 끝나면
방이 `FINISHED` 로 닫혀서 그 친구가 같이 할 "다음 판"이 없다. 티츄만 '한 판 더'(D-82)가 있다.

## 사용자 결정 (2026-10-30)

- 판이 끝나면 **같은 방 대기실로 돌아간다**. 방장이 다시 "N명으로 시작"(D-143)을 누르면 다음 판이 시작된다.
- 판 도중에 들어와 관전하던 사람은 대기실로 돌아갈 때 **자동으로 자리에 앉는다**. 게임 최대 인원까지, 들어온 순서대로 앉고 넘치는 사람은
  계속 관전한다.

## 동작

1. **정상 종료(친구와 하기 방)** — 서버는 `FINISHED` 대신 방을 `WAITING` 으로 돌린다(Lua 하나로 원자적으로).
   - 정원을 게임 최대 인원으로 되돌린다(D-143 의 시작이 정원을 그때 인원으로 줄였으므로).
   - 준비 표식을 비운다.
   - 관전자를 들어온 순서대로 빈자리에 앉힌다. 넘치는 사람은 관전자로 남는다.
   - 방 목록(`rooms:open`)에 다시 올린다. 대기 중인 방이라 다른 사람도 입장할 수 있다.
   - 매치 기록·ELO·전적은 지금처럼 종료 이벤트에서 따로 처리한다.
2. **봇과 연습 방** — 지금처럼 `FINISHED`(연습은 한 판으로 끝). 바꾸지 않는다.
3. **탈주로 끝난 판·방장 강제 종료** — 지금처럼 `FINISHED`. 정상 종료만 대기실로 돌아간다.
4. **관전 중 안내** — 진행 중인 방을 관전하는 사람에게 "다음 판부터 함께해요"를 보인다. 빈자리가 없으면 "자리가 나면"으로 바꾼다.
5. **화면 전환** — 이 세션이 판의 끝(IN_GAME→WAITING)을 보면 게임판을 바로 내리지 않는다. 결과 화면 아래 **[대기실로]** 버튼으로
   넘어간다(D-120 의 "종료 화면 유지"와 같은 방식). 처음부터 대기실을 받으면 바로 대기실이다.
6. **나가기** — 대기실로 돌아간 뒤의 나가기는 탈주가 아니다(대기실 나가기, D-134 유예 그대로).

## 바뀌는 곳 (예상)

- 서버
  - `room_return_waiting.lua` 를 새로 둔다.
  - `MatchProgressService.advance` 에서 정상 종료 갈래를 바꾼다.
  - 관전 순서용 키 `room:{id}:spectators_since`(ZSET, 들어온 시각)를 둔다. 기존 SET 은 그대로 두고 함께 쓰고 지운다.
- 클라
  - `RoomPage` 에서 IN_GAME→WAITING 전이를 보면 게임판을 유지한다.
  - 원카드·스컬킹 결과 패널에 [대기실로] 버튼을 넣는다.
  - 관전 안내 문구를 넣는다.

## 결정된 질문

- **티츄도 같은 흐름이다**(사용자, 2026-10-30).
  - '한 판 더'(리매치 API·`GameDefinition.supportsRematch`)는 없앤다.
  - 방 칩은 그대로 이어진다. 새로 앉은 사람은 시작할 때 재바이인으로 기본 칩을 받는다.
  - 티츄는 4명 고정이라 관전자는 빈자리가 생길 때만 앉는다.
- **판 도중 끊긴 채 남은 플레이어** — 대기실로 돌아갈 때 라이브 세션이 없으면 D-134 대기실 끊김 유예를 건다. 돌아오지 않으면 자리를
  비운다. 걸지 않으면 유령 좌석이 다음 판에 끼게 된다.
