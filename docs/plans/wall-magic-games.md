## 1. 조사 결과

### 1.1 벽 세우기 게임 — 원작 규칙 (공개 자료 대조)

방송 시즌 2 의 감옥 매치로 처음 나왔고(나무위키 「데블스 플랜: 데스룸/5일차」 룰 요약), 시즌 3 에서는 숙소의 보드게임 "2" 판으로 나왔다
(「데블스 플랜: 데드 어게인/게임 규칙」). 시즌 3 판의 세부는 공개 문서에 없어 사이트 구현과 그 규칙 안내로 보충했다.

| 항목 | 원판(시즌 2) | "2" 판(시즌 3, 사이트 기준) |
| --- | --- | --- |
| 판 | 7×7, 바깥 테두리는 벽 | 같음 |
| 인원·말 | 1R 3인 각 2개 / 2R 1:1 각 4개(2개는 시작 칸 고정) | 3인 각 2개(곧게 1·꺾어 1) / 1:1 각 4개(꺾어 2개 고정 + 곧게 2개 배치) |
| 배치 | 뱀 순서(1-2-3-3-2-1)로 한 개씩 빈 칸에 | 같음(1:1 은 곧게 말만 번갈아) |
| 이동 | 말 하나를 상하좌우 1~2칸, 꺾기·되돌아오기 허용, 다른 말·벽 통과 불가 | **곧게 말**: 한 방향 1~2칸 / **꺾어 말**: 1칸, 또는 1칸 뒤 좌·우로 꺾어 1칸(곧게 2칸 불가) / **제자리 불가** |
| 벽 | 이동을 마친 말의 네 면 중 벽 없는 면 하나에 **반드시** | 같음. 테두리 면은 못 고름(사이트에서 확인) |
| 벽 부수기 | 1인 1회, 이동 경로의 벽 하나를 부수고 지나감(3인 라운드만) | 같음 |
| 시간 | 차례 90초(이동+벽 합산). 넘기면 임의의 면에 벽 | 같음(사이트: 60·90·무제한) |
| 끝 | 각자의 공간이 벽으로 모두 분리되면 즉시 | 같음 |
| 점수 | 내 말이 있는 공간의 칸 수 합. 동점이면 가장 큰 단일 공간 | 같음 |

사이트에서 직접 해 본 UI 흐름(1:1 로컬): 배치(말 종류 고르기 → 빈 칸 탭, 번갈아) → 내 차례 말 탭 → 갈 수 있는 칸 강조 → 칸 탭 →
말 주변에 벽 후보 테두리 + 아래 "위·아래·왼·오른쪽 벽" 버튼(테두리 쪽은 비활성) + "이동 취소" → 벽 확정이 차례 끝. 옆 칸에
양쪽의 "확정 영역"(최대 단일 방 포함)·경합 구역 수를 실시간으로 보여 준다. 시간은 이동과 벽을 합친 한 차례 단위로 흐른다.

**원작이 정하지 않아 우리가 정해야 하는 것**: 벽 세울 면이 하나도 없는 칸으로 이동, 움직일 수 있는 말이 없는 차례, 모두가 멈췄는데
섞인 공간이 남은 경우, 부순 면에 다시 벽을 세울 수 있는지 — §2.1 에서 정한다.

### 1.2 마방진 — 원작은 "혼자 푸는 시험", 사이트도 혼자 퍼즐

- 방송 시즌 3 에서는 탈락자들이 머무는 곳의 부활 시험(1시간 제한, 혼자 도전)으로 나왔고, 1의 자리가 고정된 7×7 로 추정된다(공개 문서 추정치).
  대결 게임이 아니다.
- 사이트(직접 풀어 봄, 3×3): 크기 3~7 선택, "퍼즐(단서 몇 칸 주어짐)"/"자유 배치", 칸 탭 → 숫자판(쓴 숫자는 흐리게)·키보드 입력,
  가로·세로·대각선 합을 판 옆에 실시간 표시(맞으면 초록), 완성 줄 수·경과 시간·이동 횟수·최고 기록, 힌트·되돌리기, 완성 축하 연출. 혼자 한다.
- 수학 사실(공용): 1~N² 을 한 번씩, 모든 가로·세로·두 대각선의 합 M = N(N²+1)/2 (3·4·5 → 15·34·65). 3×3 은 회전·반사를 빼면 해가 1개,
  4×4 는 880개, 5×5 는 약 2.75억 개 — **단서와 맞는 해가 여럿일 수 있으므로 "우리 정답과 같나"가 아니라 "마방진인가"로 판정해야 한다.**
- 미르보드는 턴제 **여럿** 플랫폼이라 혼자 퍼즐을 그대로 옮기면 얏추 1인 판 같은 곁가지가 된다. 그래서 B 는 "같은 퍼즐 동시 레이스"를
  추천하고(§3), 다른 형식은 §8 M1 선택지로 남긴다.

### 2.2 우리 판 — 테마·시각

- **세계관**: 해 질 녘 언덕 목장. 내 동물이 뛰어노는 풀밭을 울타리로 두른다. 동물은 좌석 색 목도리/방울로 구분(색약 대비: 무늬도 다르게 — 점·줄·체크).
- **동물 그림**: 직접 그린 인라인 SVG 2종(황소 = 앞을 보는 단단한 실루엣, 화살표 대신 "돌진 자국" / 토끼 = 귀가 꺾인 실루엣, 발자국 "ㄱ"자).
  id 금지·`currentColor` 로 좌석 색을 받는 티츄 `tichuArt.tsx` 방식.
- **울타리**: 칸 사이 선 위에 나무 말뚝 두 개 + 가로대. 박힐 때 위에서 툭 떨어지는 0.2초 연출 + "통" 마림바풍 소리(`tableSfx`, D-271 톤).
- **땅 표시**: 확정된 내 구역은 풀색이 좌석 색으로 은은히 물든다(꽃이 피는 작은 점 무늬). 경합 구역은 그대로.
- **점수 띠**: 좌석마다 "확정 땅 N칸 · 가장 큰 마당 M칸".
- 테마 층은 원카드·티츄처럼 상수 하나로 끌 수 있게(`pastureTheme`), 동작 줄이기면 연출 생략.

├── rules/   Moves(황소·토끼 경로 전수, 넘기 경로) · Setup(고정 칸·뱀 순서) · EndRule · Scoring

- **액션 `MOVE{animalId, path, fence, jump}`** — `path` 는 방향 목록(황소 [U,U] / 토끼 [U,L]). 토끼는 같은 도착 칸에 길이 둘일 수 있어 경로를
  명시한다(어느 길이 막혔는지·넘기가 어느 울타리를 없앨지가 경로에 달림). 서버가 경로 합법성·도착·울타리 면을 다시 검증한다(Server-Authoritative).
- **이벤트(공개·순번)**: `ANIMAL_PLACED{seat, animalId, kind, cell}`, `ANIMAL_MOVED{seat, animalId, path, to, fence, jumpedFence?, sealed[]}`
  (`sealed` = 이번 수로 확정된 구역 — 클라 연출용), `TURN_CHANGED{seat, phase}`, `TURN_SKIPPED{seat}`, `SEAT_DESERTED{seat}`,
  `MATCH_ENDED{scores, largest, ranking, reason}`.
- **시간 초과**: `timeoutAction` = 합법 수 목록의 결정적 첫 원소(배치면 빈 칸 첫 칸). 원작의 "임의의 면에 벽"에 대응. 봇 정책과 섞지 않는다.
- **봇(`BOT_LEVEL`)** — 공개 정보만 담은 뷰, `random` 미사용(결정적):
  - 쉬움: 자기 동물을 3면 울타리에 가두지 않는 수 중 확정 땅 증가가 큰 수, 동점이 많으면 뷰 해시로 고르기(약하게).
  - 보통: 1수 전수 × 평가 = 확정 땅 × w1 + **보로노이 땅**(울타리 따라 BFS 최단 거리로 가장 가까운 사람의 땅) × w2 − 위험(3면 갇힘·2면 + 상대 인접) × w3.
  - 어려움: 2인은 2수 알파베타(노드 상한), 3인은 보통 + "1등 견제"(선두와 가까운 구역 막기). 오목 노트대로 **방 락 2초 TTL 안, p99 150ms**를
    노드 상한으로 맞춘다(시간 상한은 결정성을 깬다).
  - 정책이 예외·비합법 수를 내면 ERROR 로그 후 `timeoutAction` 폴백(포트 권장 패턴).
- **기록**: Flyway 다음 번호(지금 V20 → **V21 예정**) `pasture_match_results`·`pasture_match_participants`(점수·최대 구역·순위·탈주).
  `users` 무변경. 게스트·봇이 끼면 ELO 미적용(`RatedMatchPolicy`).

### 3.2 우리 판 — 테마·시각

- **세계관**: 밤하늘 관측소. 칸은 별, 숫자는 별의 밝기. 한 줄의 합이 맞으면 그 줄의 별들이 **별자리 선으로 이어져** 빛난다.
  다 맞으면 판 전체가 하나의 별자리가 되어 반짝인다(동작 줄이기면 정지 화면).
- **합 표시**: 각 줄 끝에 작은 달 모양 칩 — 비었음/모자람(아래 화살표)/넘침(위 화살표)/맞음(빛남). 색만으로 구분하지 않는다.
- **숫자판**: 1~N² 단추. 이미 쓴 숫자는 별이 꺼진 모양 + `aria-disabled`(다시 누르면 그 칸으로 이동 안내).
- **상대 띠**: 좌석마다 작은 망원경 + "★ 7/10줄 · 14/16칸", 완성하면 유성 연출 + "1등!" 도장.
- 그림·소리 직접 제작(SVG·`tableSfx` 합성음). 이름 후보는 §8 M2.

### 3.4 서버 설계 — 퍼즐은 미리 만들어 둔다

- **런타임에 풀거나 생성하지 않는다** — 운영 VM(shared-cpu-1x)과 방 락 2초를 생각해, 퍼즐은 **오프라인 도구로 만든 자원 파일**에서 꺼낸다.
  - 생성 도구(테스트 소스의 실행형 도구, 저장소 안 우리 코드): 무작위 마방진(3×3 8개 / 4×4 전수 7,040개 / 5×5 무작위 탐색으로 수천 개) →
    단서 칸 고르기 → **풀이기로 난이도 측정**(단서와 맞는 해 수, 백트래킹 노드 수) → 난이도 띠에 드는 것만 남김.
  - 자원: `resources/starsquare/puzzles-{level}.json`(퍼즐당 단서 + 측정 해 하나). 런타임은 고른 퍼즐에 **대칭 변환**(회전·반사 8 × 보수 n²+1−x 2)을
    입혀 같은 난이도로 16배 다양화만 한다 — 모두 마방진 성질을 보존한다(테스트로 고정).
  - 퍼즐 수는 띠마다 200~500개(파일 수십 KB).
- 판정 `MagicCheck.isMagic(grid, clues)` — 순수 함수, 전수 테스트(3×3 의 9! 배열 전부에서 마방진 8개만 참).
- **진행도**: `SYNC` 마다 채운 칸·맞은 줄 수 계산 → 바뀌었을 때만 `PROGRESS` 방송(같은 값이면 이벤트 없음 — 방송량 억제).
- **SYNC 검증**: 길이 N², 값 0(빈칸)·1~N², 단서 칸 불변, `version` 단조(낡은 SYNC 무시). 중간 상태의 중복 숫자는 허용(완성 판정에서 걸러짐).
- **봇 = 페이스 모델**: 퍼즐 시작 때 좌석별 완성 시각을 뷰 해시 시드로 정한다(난이도 × `BOT_LEVEL` 분포 — 쉬움 느림, 어려움은 보통 사람 중앙값보다 조금 빠르게, S1 에서
  사람 측정치가 없으니 잠정값 + 운영 뒤 조정). 이정표마다 엔진 타이머가 봇의 `PROGRESS` 를 올리고, 완성 시각에 `SOLVED`. 봇은 수를 고르지 않으므로
  "공개 정보만" 원칙과 부딪히지 않는다(봇 판은 퍼즐이 끝날 때 측정 해로 공개).
- 매치 시작 때 퍼즐 R개를 미리 골라 상태에 둔다(같은 매치에서 겹치지 않게). 정답은 상태 JSON 안에만 — **공개 뷰·이벤트 직렬화 타입에 필드 자체가 없다**(타입 분리로 은닉).

```
domain.game.starsquare
├── StarSquareGameDefinition (ID "STAR_SQUARE", 1~4, MATCH_LENGTH·BOT_LEVEL·DIFFICULTY, 턴 제한 선택 180·300·600 기본 300)
├── StarSquareEngine / StarSquareGameEngine
├── puzzle/  Grid · MagicCheck · Symmetry · PuzzleBank(자원 읽기) · Progress

```
