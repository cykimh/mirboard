# 요트 룰 명세 (Yacht Dice Rules)

본 문서는 Mirboard 요트 룰의 **단일 진실 공급원**이다. 코드(S2 순수 엔진)는 이 문서를 따르고, 어긋나면 코드를 고치거나 이 문서와
결정(`docs/decisions.md`)을 함께 고친다. 각 절 끝의 **코드:** / **테스트:** 는 `rules-onecard.md` 와 같은 표기이고, 경로는
`server/src/{main,test}/java/com/mirboard/domain/game/yacht/` 기준, 위치는 메서드 이름으로 적는다. S1 시점에는 코드가 없으므로
**코드(S2 예정):** 로 만들 자리를 적어 두고, S2 에서 실제 이름으로 바꾼다. 어댑터·봇·기록은 S3, 클라는 S4 에서 같은 방식으로 덧붙인다 —
클라는 판정하지 않으며 표시만 한다(권위는 서버, 후보 점수도 서버가 계산).

> **출처와 하우스 룰.** 주사위 5개·12칸을 쓰는 일반 공용 룰만 다룬다(특정 상표 게임의 이름·점수표 디자인은 쓰지 않는다). 원문마다 갈리거나
> 답하지 않는 항목을 우리가 정한 것은 본문에 **[결정]** 으로 표시하고 §10 에 모았다. 설계 배경은 `docs/plans/yacht.md`, 결정은 D-181~D-183.

## 1. 도구

| 구분 | 내용 | 코드 표기 |
| --- | --- | --- |
| 주사위 | 6면체 5개, 눈 1~6. 위치(0~4)로 구분한다 | `Dice` — 길이 5 정수 배열, 각 1~6 |
| 홀드 | 주사위마다 고정 여부 | `HoldMask` — 5비트(위치 i 가 비트 i) |
| 점수표 | 좌석마다 12칸, 칸마다 "빈 칸" 또는 점수(0 이상) | `Scorecard` — `Map<Category, Integer>`(빈 칸은 키 없음) |

- 주사위 눈은 **굴리는 순간 서버가 정한다**. 상태에 미래 눈·시드·난수기 상태를 두지 않는다 **[결정]**(D-182).
- **코드(S2 예정):** `dice/Dice`, `dice/HoldMask`, `dice/DiceRoller`(눈 하나를 주는 함수형 인터페이스 — 테스트는 정해진 눈을, 어댑터는 `Random` 을 주입), `score/Scorecard`.

## 2. 인원과 좌석

| 항목 | 값 |
| --- | --- |
| 인원 | 1~4 (D-181). 친구 방 정원 4, 방장이 "N명으로 시작" |
| 1인 | 허용. 결과·참가자·전적 기록 없음(§9.3) |
| 봇 | 대기실 [빈자리 봇으로 채우기](D-174). 봇과 사람의 룰은 같다 |
| 좌석 | 0 부터. 좌석 순서는 방의 좌석 정책을 따른다(엔진은 받은 순서 그대로) |
| 차례 순서 | 좌석 오름차순, 탈주자 건너뜀. 좌석 +1 이 다음 사람(D-132 의 시계 방향과 같다) |

- **코드(S2 예정):** `YachtEngine.start(seatCount, now)`, `YachtEngine.nextSeat`.

## 3. 매치 진행

1. 매치는 **12라운드**다. 라운드마다 살아 있는 좌석이 차례 순서대로 **한 차례씩** 한다.
2. 첫 라운드 첫 차례는 **좌석 0** **[결정]** — 모두 같은 횟수를 하므로 선 이점이 없다.
3. 라운드의 마지막 살아 있는 좌석이 기록하면 다음 라운드가 되고, 가장 작은 살아 있는 좌석부터 다시 시작한다.
4. 살아 있는 좌석 전원이 12칸을 다 채우면 매치가 끝난다(§8). 1판 = 1매치.

- 라운드 r 에 차례를 기다리는 좌석은 r−1 칸, 이미 한 좌석은 r 칸을 채웠다(§11 불변식).
- **코드(S2 예정):** `YachtEngine.endTurn`(다음 좌석·라운드·종료 판정 한 곳).

## 4. 한 차례

차례는 `TURN_CHANGED` 로 시작한다. 그때 주사위는 비어 있고(굴린 횟수 0) 홀드는 모두 풀린다.

| 할 수 있는 것 | 언제 | 결과 |
| --- | --- | --- |
| `ROLL` 굴리기 | 굴린 횟수 0·1·2 | 홀드하지 않은 주사위를 새로 굴린다. 횟수 +1 |
| `HOLD` 홀드 바꾸기 | 굴린 횟수 1·2 | 홀드 마스크를 통째로 바꾼다 |
| `SCORE` 기록하기 | 굴린 횟수 1·2·3 | 빈 칸 하나에 지금 주사위의 점수를 적고 차례 끝 |

1. **첫 굴림**은 5개 전부다. `ROLL` 에 `held` 를 실어 보내면 첫 굴림에서는 모두 false 여야 한다(아니면 `HOLD_NOT_ALLOWED`).
2. **2·3번째 굴림**은 홀드하지 않은 주사위만 굴린다. `ROLL` 에 `held` 가 있으면 먼저 그 홀드를 적용하고 굴린다 — `HOLD` 이벤트가 늦게 도착해도
   굴림이 의도대로 되게 하는 것이다. 이때 홀드가 바뀌면 `DICE_HELD` 를 먼저 발행한다.
3. **5개 모두 홀드한 채 굴리기**는 거절한다(`NOTHING_TO_ROLL`) **[결정]** — 굴림 횟수만 날리는 실수다.
4. **홀드 바꾸기**는 굴림 1·2번째 뒤에만 받는다. 첫 굴림 전·3번째 굴림 뒤에는 `HOLD_NOT_ALLOWED`. 지금 홀드와 같은 마스크는 `HOLD_UNCHANGED`
   **[결정]**(빈 전이로 이벤트·세대만 쓰지 않게).
5. **기록**은 1번 이상 굴린 뒤 빈 칸에만 한다. 조건이 안 맞는 칸에 적으면 0점("버리기") — 서버는 그대로 받는다(0점 확인 창은 클라 UX).
6. 3번째 굴림 뒤에는 기록만 할 수 있다(`ROLL` → `NO_ROLLS_LEFT`, `HOLD` → `HOLD_NOT_ALLOWED`).
7. 차례가 아닌 좌석의 액션은 `NOT_YOUR_TURN`, 끝난 매치의 액션은 `MATCH_OVER`, 탈주한 좌석의 액션은 `NOT_YOUR_TURN`.

- 굴릴 때마다 서버는 그 좌석의 **빈 칸 전부에 대한 후보 점수**(0 포함)를 계산해 `DICE_ROLLED` 와 공개 뷰에 싣는다 **[결정]**(D-182 — 클라 룰 미러 없음).
- **코드(S2 예정):** `YachtEngine.roll` · `hold` · `score`, `action/YachtAction`(sealed `Roll`·`Hold`·`Score`), `action/RejectionReason`.
- **테스트(S2 예정):** `YachtEngineTurnTest` — 표의 각 행과 1~7 의 거절 사유마다 하나.

### 4.1 거절 사유 (`ERROR`, 비공개)

| 사유 | 경우 |
| --- | --- |
| `NOT_YOUR_TURN` | 차례가 아님(탈주한 좌석 포함) |
| `MATCH_OVER` | 매치가 끝남 |
| `NO_ROLLS_LEFT` | 3번 굴린 뒤 `ROLL` |
| `NOTHING_TO_ROLL` | 5개 모두 홀드하고 `ROLL` |
| `HOLD_NOT_ALLOWED` | 첫 굴림 전·3번째 굴림 뒤 `HOLD`, 첫 굴림의 `held` 에 true |
| `HOLD_UNCHANGED` | 지금과 같은 홀드로 `HOLD` |
| `NOT_ROLLED_YET` | 굴리기 전 `SCORE` |
| `CATEGORY_FILLED` | 이미 채운 칸에 `SCORE` |
| `INVALID_ACTION` | 형식 오류(`held` 길이 ≠ 5, 알 수 없는 칸) — 역직렬화 단계 |

거절은 상태를 바꾸지 않는다.

## 5. 점수표 (12칸)

점수는 **주사위 5개 눈 d₁…d₅** 로만 정한다. `count(v)` = 눈 v 인 주사위 수, `sum` = 다섯 눈의 합.

| 순서 | 칸 (`Category`) | 이름 | 조건 | 점수 |
| --- | --- | --- | --- | --- |
| 1 | `ONES` | 1 | 없음 | `1 × count(1)` |
| 2 | `TWOS` | 2 | 없음 | `2 × count(2)` |
| 3 | `THREES` | 3 | 없음 | `3 × count(3)` |
| 4 | `FOURS` | 4 | 없음 | `4 × count(4)` |
| 5 | `FIVES` | 5 | 없음 | `5 × count(5)` |
| 6 | `SIXES` | 6 | 없음 | `6 × count(6)` |
| 7 | `CHOICE` | 초이스 | 없음 | `sum` |
| 8 | `FOUR_OF_A_KIND` | 포 카드 | 어떤 v 의 `count(v) ≥ 4` | `sum` **[결정]**(네 개 합이 아니라 다섯 개 합) |
| 9 | `FULL_HOUSE` | 풀 하우스 | 눈별 개수가 {3, 2}, **또는 {5}** **[결정]** | `sum` |
| 10 | `SMALL_STRAIGHT` | 스몰 스트레이트 | 눈 집합이 {1,2,3,4}·{2,3,4,5}·{3,4,5,6} 중 하나를 포함 | 15 |
| 11 | `LARGE_STRAIGHT` | 라지 스트레이트 | 눈 집합이 {1,2,3,4,5} 또는 {2,3,4,5,6} | 30 |
| 12 | `YACHT` | 요트 | 어떤 v 의 `count(v) = 5` | 50 |

조건이 안 맞으면 0점이다.

### 5.1 상단 보너스·총점

- **상단 소계** = 1~6 칸 점수의 합(빈 칸은 0).
- **보너스** = 상단 소계 ≥ 63 이면 **35**, 아니면 0. 칸이 아니라 계산값이고, 63 에 닿는 순간부터 총점에 들어간다.
- **총점** = 12칸 점수의 합(빈 칸은 0) + 보너스.
- 최고점 **325** = 상단 105 + 보너스 35 + 초이스 30 + 포 카드 30 + 풀 하우스 30(6 다섯 개 — 5개 같음 인정) + 15 + 30 + 50.

### 5.2 겹치는 조합 (예시로 확정)

| 주사위 | 성립하는 특수 칸 | 메모 |
| --- | --- | --- |
| 6 6 6 6 6 | 포 카드 30 · 풀 하우스 30 · 요트 50 | 5개 같음은 세 칸 모두 성립 |
| 3 3 3 3 5 | 포 카드 17 | 풀 하우스 아님({4,1}) |
| 2 2 3 3 3 | 풀 하우스 13 | |
| 1 2 3 4 5 | 스몰 15 · 라지 30 | 라지는 스몰을 포함 |
| 1 2 3 4 6 | 스몰 15 | |
| 1 3 4 5 6 | 스몰 15 | {3,4,5,6} 포함 |
| 2 3 4 4 5 | 스몰 15 | 같은 눈이 끼어도 집합으로 본다 |
| 1 2 3 5 6 | 없음 | |

- 요트 추가 보너스·조커 규칙, 13칸 변형은 **없다**(§12).
- **코드(S2 예정):** `score/Category`(enum, 위 순서), `score/Scoring.points(Category, Dice)`, `score/Scoring.candidates(Scorecard, Dice)`, `score/Scorecard.upperSubtotal`·`bonus`·`total`.
- **테스트(S2 예정):** `ScoringTest`(§5.2 표 각 행) + `ScoringExhaustiveTest`(6⁵ = 7,776 조합 × 12칸을 이 표에서 직접 쓴 독립 기대값 함수와 대조 —
  같은 구현을 두 번 쓰지 않게 기대값 함수는 눈별 개수 배열만으로 쓴다), `ScorecardTest`(보너스 경계 62·63, 최고점 325).

## 6. 차례 제한과 자동 처리

1. 방의 턴 제한(`turnSeconds`, D-183 — 0 이면 끔)은 **차례 전체** 시간이다. 차례 시작 시각은 `TURN_CHANGED` 를 만드는 전이가 상태에 기록한다.
   홀드·굴림을 해도 다시 세지 않는다.
2. 시간이 다 되면 서버가 차례를 끝낸다(엔진 타이머 발화, `GameAction` 이 아니라 시스템 전이 — 클라가 만들 수 없다):
   - 아직 안 굴렸으면 5개를 한 번 굴린다(`DICE_ROLLED`, 굴린 횟수 1).
   - 지금 주사위로 **점수가 가장 높은 빈 칸**에 기록한다. 같으면 §5 표의 **위쪽 칸** **[결정]**. `SCORED.auto = true`.
3. 턴 제한 기본 45초, 선택지 끔·20·30·45·60(D-182).
4. **폴백 `timeoutAction`**(인프라 턴 데드라인이 먼저 닿는 드문 경우·봇 정책 실패): 안 굴렸으면 `ROLL`, 아니면 위 2 의 칸으로 `SCORE`. 결정적이다.

- **코드(S2 예정):** `YachtEngine.remaining(state, turnSeconds, now)`(남은 시간 — 0 이하면 만기), `YachtEngine.expire(state, now, roller)`(위 2),
  `YachtEngine.fallbackAction(state)`(위 4). 시계는 인자로 받는다(순수 엔진에 시계 없음). 어댑터의 포트 ⑦ `timer`/`onTimer` 연결은 S3.
- **테스트(S2 예정):** `YachtEngineTimeoutTest` — 안 굴림/1·2·3번 굴림 뒤 만기, 동점 칸 순서, 홀드를 여러 번 바꿔도 남은 시간이 줄기만 함, 끔이면 없음.

## 7. 탈주

1. 탈주한 좌석은 **차례에서 빠지고 점수표가 그 자리에서 멈춘다**. 좌석은 방에 남는다(D-122).
2. 탈주자 차례였으면 그 차례는 기록 없이 끝나고(주사위·홀드 비움) 다음 살아 있는 좌석으로 넘어간다. 그가 라운드의 마지막이었으면 다음 라운드.
3. 탈주 뒤 판정, 위에서부터:
   - 살아 있는 좌석 전원이 12칸을 다 채웠으면 → `FINISHED`.
   - 살아 있는 **사람**이 없으면(봇만 남음 — 1인 방의 탈주 포함) → `NO_HUMANS`, 현재 총점으로 순위.
   - 그 밖 → 계속(`MATCH_CONTINUES`). 사람이 1명만 남아도 계속한다 **[결정]**(1인 플레이가 허용된 게임이다).
4. 이미 탈주한 좌석의 다시 탈주는 해당 없음(`NOT_APPLICABLE`).

- **코드(S2 예정):** `YachtEngine.desert(state, seat, humanSeats)`. 사람 좌석은 어댑터가 `GameContext.botSeats` 로 알려 준다.
- **테스트(S2 예정):** `YachtEngineDesertionTest` — 차례 중 탈주·차례 아닐 때·라운드 마지막 좌석·12라운드 마지막 좌석(→ `FINISHED`)·마지막 사람(→ `NO_HUMANS`)·
  사람 1명 남음(→ 계속)·이중 탈주.

## 8. 종료와 순위

### 8.1 종료 사유

| 사유 | 조건 |
| --- | --- |
| `FINISHED` | 살아 있는 좌석 전원이 12칸을 채움 |
| `NO_HUMANS` | 탈주로 살아 있는 사람이 없음(§7-3) |
| `ACTION_LIMIT` | 성공한 액션 수가 상한 `좌석 수 × 12 × 40` 에 닿음 **[결정]** — 남은 빈 칸을 0 으로 보고 현재 총점으로 |

- `ACTION_LIMIT` 은 홀드를 끝없이 바꾸는 클라에 대한 안전장치다. 정상 판의 차례당 액션은 6~10개(굴림 최대 3 + 홀드 몇 번 + 기록)라 상한(차례당 40)에 닿을 일이 없고,
  시뮬레이션에서 발생 0 을 확인한다.

### 8.2 순위

1. 살아 있는 좌석(끝까지 남은 사람과 봇)을 **총점 내림차순**으로 세운다.
2. 같은 총점은 **동순위**, 경쟁 순위 표기(1, 1, 3) **[결정]** — 깨는 규칙 없음.
3. 탈주자는 그 아래 **모두 같은 최하위**(탈주자끼리 동순위, 점수 무관).
4. **승리 = 1위**(동순위면 모두).

- **코드(S2 예정):** `rules/Ranking.rank(state)`, `state/MatchResult(reason, placements)`.
- **테스트(S2 예정):** `RankingTest` — 동점 2·3명, 탈주자 여럿, 1인, 전원 탈주 후 봇만.

## 9. 공개·비공개와 기록

### 9.1 공개 (`/topic/room/{roomId}`) — 전부 결과값

| type | payload |
| --- | --- |
| `TURN_CHANGED` | 좌석, 라운드, 차례 제한(초, 0 = 끔) |
| `DICE_HELD` | 좌석, `held`(5개) |
| `DICE_ROLLED` | 좌석, 주사위 5개, `held`, 굴린 횟수, 후보 점수(빈 칸 → 점수) |
| `SCORED` | 좌석, 칸, 점수, 그 좌석의 상단 소계·보너스·총점, `auto` |
| `PLAYER_ELIMINATED` | 좌석, 사유 `DESERTED`, 멈춘 총점 |
| `MATCH_ENDED` | 사유, 순위(좌석·총점·순위) |

- 한 전이의 이벤트 순서: `DICE_HELD`(바뀐 경우) → `DICE_ROLLED` / `SCORED` → (`PLAYER_ELIMINATED`) → `TURN_CHANGED` 또는 `MATCH_ENDED`.
- 시작 상태는 resync 로 받는다. 시작 직후 첫 `TURN_CHANGED` 하나만 발행한다(`MATCH_STARTED` 없음).

### 9.2 비공개 (`/user/queue/room/{roomId}`)

- `ERROR`(§4.1)뿐이다. 순번을 쓰지 않는다(`sequenced()` = false, D-126).
- 비공개 뷰는 없다(`privateView` = empty). 숨길 정보가 없다 — 공개 뷰가 상태의 전부를 보인다(난수기는 상태에 없다).

### 9.3 기록

- 2인 이상 매치: 매치 기록기 계약(`docs/game-port.md` "매치 기록기 계약") 그대로 — 비봇 참가자마다 전적, 봇·게스트가 끼면 ELO 미적용,
  ELO 는 개인전(`applyFreeForAll`, 점수 = 좌석 수 − 순위), 탈주는 `deserted`.
- **1인 매치: 아무것도 쓰지 않는다**(결과·참가자·`user_game_stats` — D-181). 1인 + 봇은 2인 이상 매치다.
- 상대 전적: 최종 순위로 센다.

- **코드(S2 예정):** `event/YachtEvent`(sealed), `state/YachtStateMapper.toPublicView`. 기록기·상대 전적은 S3.
- **테스트(S2 예정):** `YachtJsonRoundTripTest`(상태·액션·이벤트 JSON 왕복, envelope 이름, 상태 JSON 에 난수 관련 키 없음),
  시뮬레이션의 "이벤트만 듣는 클라" 대조(§11).

## 11. 검증 기준 (S2)

- **점수 전수**: §5 의 7,776 × 12 대조(§5 테스트).
- **불변식**(매 전이 뒤, `invariant/YachtInvariantChecker`):
  - 주사위가 비었으면 굴린 횟수 0, 아니면 1~3이고 눈은 1~6. 굴린 횟수 0 이면 홀드는 모두 false.
  - 라운드 r(1~12)에서 살아 있는 좌석의 채운 칸 수는 차례 순서상 앞이면 r, 뒤(지금 차례 포함)면 r−1. 탈주자는 검사하지 않는다.
  - 상단 소계·보너스·총점이 칸에서 다시 계산한 값과 같다.
  - 끝나지 않은 판: 차례 좌석은 살아 있는 좌석, 살아 있는 사람 ≥ 1, 액션 수 < 상한. 끝난 판: 차례 좌석 −1, 사유별 조건(§8.1)이 성립.
- **시뮬레이션**(`YachtMatchSimulationTest`): 1~4인 무작위 봇(합법수 균등) 인원별 2,000판 + 사람 1·봇 3 300판이 전부 끝나고, 매 전이 불변식을 통과한다.
  `ACTION_LIMIT` 발생 수를 기록한다(무작위 봇은 홀드를 많이 바꾸므로 0 이 아닐 수 있다 — 그 비율이 1% 미만인지 본다. 휴리스틱 봇은 S3 에서 0 을 요구).
  이벤트만 듣는 클라이언트가 그린 공개 상태와 엔진의 공개 뷰가 매 전이 같다.
- **거절**: §4.1 의 모든 사유마다 단위 테스트, 거절 뒤 상태 불변.
- **시간 초과·탈주**: §6·§7 테스트 목록.
- **결정성**: 같은 `DiceRoller` 수열이면 같은 판(이벤트 목록이 같다).
