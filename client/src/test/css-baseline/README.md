# CSS 회귀 기준선 (D-94)

`styles.css` 를 검증하는 자동 테스트는 없다 — 이게 T5 의 최대 위험이었다.
그래서 리팩토링 **전에** 라이브 브라우저에서 계산 스타일(computed style) 다이제스트를
떠두고, 리팩토링 후 같은 방식으로 떠서 비교한다.

## 왜 해시인가

셀렉터 37개 × CSS 속성 30개 × 폭 3종은 전문 비교하기엔 크다. 셀렉터별로 FNV 해시를
떠서 **어긋난 셀렉터만** 골라낸 뒤, 그 셀렉터만 전문 비교한다.

## 캡처 방법

1. 서버·클라를 띄우고 봇 솔로 방으로 **PLAYING 단계 + 채팅 패널 열림** 상태를 만든다
   (이 조합이 arena/hand/header/chat 표면을 가장 넓게 덮는다).
2. 브라우저 콘솔에서 `snapshot.js` 의 함수를 정의한 뒤 폭 401 / 520 / 1280 에서
   `__digest()` 를 호출한다.
3. 결과를 `baseline.json` 과 비교한다.

## 한계 (정직하게)

- 도달하지 못한 상태는 안 덮인다: `.match-ended` `.arena-pass` `.pass-slot`
  `.combo-hint` `.turn-countdown` `.seat-chips` `.declared` `.status-tag` `.error`.
  이들을 바꾸는 변경은 **육안 확인이 필요**하다.
- `.room-chat-report` 는 본인 메시지엔 안 붙어서(D-93 자기신고 가드) 캡처 시
  상대 메시지가 있어야 한다.
- 브라우저 패널 폭이 실제로 401 미만이면 오버라이드가 입력 좌표와 어긋난다(D-88 참조).
  계산 스타일 자체는 정상이므로 이 용도에는 무관하다.
